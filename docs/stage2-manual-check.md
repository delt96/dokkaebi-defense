# 2단계 멀티플레이 수동 확인 안내

자동 시험으로는 볼 수 없는 부분을 사람이 두 브라우저로 직접 확인하는 순서다. 명세 10장 "두 브라우저 수동 확인" 1~5번과, 계획 Task 22에서 화면으로 봐야 한다고 남긴 6~11번을 함께 다룬다.

## 1. 실행 방법

둘 중 하나로 띄운다.

**배포와 같은 방식 (한 주소)**

```
npm start
```

클라이언트를 빌드한 뒤 서버가 화면과 게임 서버를 함께 `http://localhost:2567`에서 띄운다. 포트를 바꾸려면 `PORT=3000 npm start`처럼 준다. 이미 개발 서버가 2567을 쓰고 있으면 먼저 끄거나 다른 포트를 쓴다.

**개발 방식 (서버와 화면을 따로)**

```
npm run dev:server   # 게임 서버, http://localhost:2567 (파일을 고치면 다시 뜸)
npm run dev          # 화면(Vite), http://localhost:5173
```

이때 브라우저로는 `http://localhost:5173`에 들어간다. 화면은 자동으로 2567의 서버에 붙는다.

## 2. 두 브라우저로 들어가는 법

지금 화면에서 만드는 방은 모두 60라운드다. 20라운드 방은 더 이상 만들 수 없으므로, 아래에서 20라운드를 전제로 한 항목은 당시 점검 기록으로 읽는다.

1. 첫 번째 브라우저(예: Chrome)에서 위 주소를 열고 닉네임을 넣은 뒤 '방 만들기'를 누른다.
2. 대기실에서 '링크 복사'를 눌러 `/room/<방 번호>` 주소를 복사한다.
3. 두 번째 브라우저(예: Edge)에 그 주소를 붙여 넣고 다른 닉네임으로 '입장하기'를 누른다. 같은 닉네임은 거절된다.
4. 둘 다 '준비'를 누르면 방장(먼저 만든 쪽)이 '시작'을 누를 수 있다.

확인은 서로 다른 브라우저로 한다. 같은 브라우저라도 새 탭에 링크를 붙여 넣으면 다른 사람으로 들어가지만, '탭 복제'로 연 탭은 자리 정보를 그대로 들고 가서 같은 사람으로 취급된다(10번 항목에서 이걸 쓴다).

## 3. 개발용 바로가기

후반 상황을 보려고 한 판을 처음부터 끝까지 둘 필요는 없다. 판을 원하는 틱에서 시작하게 할 수 있다. 1틱은 50ms(초당 20틱)다.

조건이 두 가지다.

- **서버**를 `DORANDI_DEV=1`로 띄운다. 이 값이 없으면 서버는 바로가기 요청을 무시한다.
- **화면**은 개발 방식(`npm run dev`, 5173)이어야 한다. `npm start`로 빌드한 화면은 주소의 `?dev=`를 읽지 않는다.

```
# Git Bash
DORANDI_DEV=1 npm run dev:server
npm run dev

# PowerShell
$env:DORANDI_DEV='1'; npm run dev:server
npm run dev
```

서버는 `DORANDI_DEV=1 npm run start -w @dorandi/server`로 띄워도 되지만, 브라우저는 어느 쪽이든 5173 주소로 연다.

방을 **만드는 쪽**이 주소 끝에 `?dev=jump<틱>`을 붙여 연다. 예: `http://localhost:5173/?dev=jump4590`. 그 상태로 방을 만들면 '시작'을 누르는 순간 판이 그 틱으로 건너뛴다. 들어오는 쪽은 복사한 링크로 평소처럼 들어오면 된다. 건너뛸 때 모든 고개의 잡귀와 불은 비워진다.

| 주소 | 시작 지점 | 쓰는 곳 |
| --- | --- | --- |
| `?dev=jump4590` | 6라운드 시작(4600틱) 0.5초 전. 첫째 탈이 바로 나온다 | 3번 역신 예고 |
| `?dev=jump7700` | 10라운드 시작(7800틱) 5초 전. 9라운드가 첫 관문 기한이다 | 5번 관문 실패 |

## 4. 확인 항목

### 사람이 처음 보는 항목 (1~5)

**1. 방 만들기와 링크 입장**
- Chrome과 Edge로 `npm start` 주소(`http://localhost:2567`)에서 방을 만들고, 복사한 링크로 입장한다.
- 두 이름과 준비 상태가 양쪽 화면에서 똑같은지 본다.
- 시작한 뒤 한쪽에서 '뚝딱!'으로 뽑아도 다른 쪽 불 개수는 그대로인지 본다.

**2. 뽑기·조합·이동 조작**
- 메뉴를 닫은 상태에서 아래쪽의 '뚝딱! (N번)'과 '보너스까지 1등급 N번'이 읽히는지 본다.
- 유닛을 하나 고른 뒤 Z / X / C 중 하나를 눌러, 고른 칸에 조합 결과가 생기는지 본다. 터치 화면이면 결과 버튼 한 번으로 조합되는지도 본다.
- 보스가 나온 뒤 보스를 따라 유닛을 옮겨 본다. 손을 뗐을 때 옆 칸이 선택되지 않는지, 놓은 유닛이 원래 칸으로 튀어 돌아가지 않는지 본다.

**3. 적 쌓기와 역신 예고**
- 한쪽은 일부러 유닛을 적게 두어 잡귀를 쌓는다. 상대 화면 왼쪽 줄에서 숫자가 늘고, 48마리부터 붉은 숫자와 '위험', 한도를 넘으면 '초과 N초'로 바뀌는 순서가 내 화면과 같은지 본다.
- 역신 예고의 마지막 1초는 3장의 바로가기로 본다. 서버를 `DORANDI_DEV=1`로 띄우고 `http://localhost:5173/?dev=jump4590`에서 방을 만든다. 시작하면 0.5초 뒤 첫째 탈이 나온다.
- 탈이 다음 고개로 넘어가기 직전에 받는 쪽 화면에 '다음은 내 고개 · N초'가 뜨는지, 넘어가는 순간 입구가 바뀌는지, 체력이 끊기지 않고 이어지는지 본다.

**4. 새로고침과 포기**
- 한쪽 탭을 새로고침한다. 그동안 상대 화면 왼쪽 줄에 '재접속 N초'가 뜨고, 끊긴 쪽 고개에서도 유닛 공격이 계속되는지 본다.
- 돌아온 뒤 자리, 엽전 잔액, 보스 위치가 끊기기 전과 맞는지 본다.
- 한쪽이 '메뉴' → '포기하고 나가기' → 확인으로 포기한다. 포기한 쪽은 넋이 되어 생존자를 관전하고, 아래 지원 카드로 엽전을 보낸다. 받는 쪽에 5냥이 정확히 한 번만 들어오는지 본다(넋은 라운드마다 지원 토큰 1개, 받는 사람도 라운드당 한 번).

**5. 판 끝내기와 다시 하기**
- 관문을 놓치는 판: 서버를 `DORANDI_DEV=1`로 띄우고 `http://localhost:5173/?dev=jump7700`에서 방을 만들어 시작한다. 5초 뒤 9라운드가 끝나면서 첫 관문을 놓쳐 '스토리 관문 실패'로 끝나야 한다.
- 한 명만 완주하는 판: 바로가기가 없으니 한 판을 끝까지 둔다(20라운드, 약 15분). 한 사람은 중간에 포기하고, 다른 사람이 끝까지 간다.
- 두 판 모두 넋이 된 사람도 같은 팀 결과 화면을 보는지, 결과의 줄을 누르면 탈락 전 기록을 읽을 수 있는지 본다.
- 두 사람이 모두 '다시 하기'를 눌러 같은 새 대기실에서 만나는지 본다. 새 방의 방장은 먼저 누른 사람이고, 닉네임은 다시 묻지 않는다.

### 자동 점검 완료, 사람이 한 번 더 볼 것 (6~11)

아래 화면은 에이전트가 640~1280px 폭에서 스크린숏으로 점검하고 고쳤다(커밋 `af6c148`). 실제 브라우저 1배율(1280×720)에서 한 번 더 눈으로 본다.

**6. 왼쪽 여섯 줄** — 자동 점검 완료, 사람이 한 번 더 볼 것
- 여덟 글자 닉네임(예: `가나다라마바사아`, `ABCDEFGH`)이 잘리지 않고 다 보이는지 본다.
- 잡귀 수, 상태 글자('생존', '위험', '재접속 N초' 등), 오른쪽 끝 역신 표식과 막대가 서로 겹치지 않는지 본다.

**7. 위쪽 두 줄과 메뉴** — 자동 점검 완료, 사람이 한 번 더 볼 것
- 위쪽 두 줄 안내와 오른쪽 위 '메뉴' 버튼이 겹치지 않는지 본다.
- 메뉴 창에 '도감', '포기하고 나가기'가 있는지, '포기하고 나가기'를 누르면 확인창이 먼저 뜨는지 본다.
- 오른쪽 아래 톱니 버튼을 누르면 설정 창이 뜨고, '조합 도우미'와 '효과 줄이기'를 켜고 끌 수 있는지 본다. Esc로 닫힌다.

**8. 조합 도우미와 도감** — 자동 점검 완료, 사람이 한 번 더 볼 것
- Q 키나 설정 창으로 연 조합 도우미가 왼쪽 여섯 줄 위를 덮고(제목 줄은 보임), 안의 조합 버튼이 눌리는지 본다.
- 도감의 40행 표가 끝까지 스크롤되는지 본다.

**9. 넋 화면** — 자동 점검 완료, 사람이 한 번 더 볼 것
- 넋 화면 아래 지원 카드가 44px 높이로 제대로 보이는지 본다.
- 왼쪽에서 살아 있는 사람의 줄을 누르면 관전 대상이 바뀌는지, 탈락한 줄은 눌리지 않는지 본다.
- 지원을 받은 쪽 오른쪽에 'N번 넋이 보낸 엽전 +5' 알림이 3초 동안 뜨는지 본다.

**10. 연결 끊김과 사라진 방** — 자동 점검 완료, 사람이 한 번 더 볼 것
- 판 도중 서버를 껐다 켜면 '연결이 끊겼습니다 · 다시 연결하는 중' 띠가 뜨는지 본다.
- 서버가 다시 뜨면 이전 방은 사라진 상태다. 화면에 '없거나 끝난 방입니다'와 '새 방 만들기'만 남는지 본다.
- 판 도중 탭을 복제(탭 우클릭 → 복제)하면, 원래 탭에 '다른 창에서 접속했습니다'가 뜨는지 본다. 새 탭에 링크만 붙여 넣으면 자리 정보가 없어 이 알림은 나오지 않는다.

**11. 팀 결과 화면** — 자동 점검 완료, 사람이 한 번 더 볼 것
- 결과의 여섯 줄 표가 칸이 어긋나지 않고, 여덟 글자 이름이 들어가는지 본다.
- 줄을 누르면 그 사람의 라운드별 잡귀 그래프가 열리는지, 탈락한 사람은 탈락한 라운드까지만 점이 찍히는지 본다.
- 결과가 뜨고 120초가 지나면 '방이 닫혔습니다'와 '새 방 만들기'가 나오는지 본다.

## 5. 함께 기록할 것

여섯 명이 실제로 한 판을 끝까지 해 본 뒤 아래를 적어 둔다. 다음 콘텐츠 작업을 정할 때 쓴다.

- 판이 끝난 뒤 누가 '다시 하기'를 눌렀나? 먼저 누른 사람, 끝까지 안 누른 사람이 있었나?
- 중간에 넋이 된 사람이 결과 화면까지 남아 있었나, 아니면 먼저 나갔나? 나갔다면 언제쯤인가?
- 그 밖에 명세 11장 1~3번 판단에 필요한 것: 첫째 탈이 앞 고개에서 죽어 뒤 고개가 한 번도 못 때린 경우가 있었는지, 넋의 5냥 지원이 동료를 고를 만큼 체감됐는지, 유닛을 고른 뒤 조합 결과를 찾느라 상세를 자주 열었는지.
