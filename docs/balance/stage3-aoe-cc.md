# 3단계 범위 기절·깍

날짜: 2026-11-28 · 브랜치 `claude/aoe-stun-shred` (기준 `744e3b8`, v7 데이터)

한 마리에만 거는 기절과 물깍/마깍은 뭉쳐 오는 웨이브에 약했다. 웨이브는 범위로, 보스는 단일로 역할을 나누기로 하고, 3단계 전용 유닛의 발동형 단일 기절·깍을 범위로 바꿨다. 범위 깍은 스킬이 발동할 때만 건다(매 타격·상시 오라가 아니다).

## 1. 바뀐 것

| 항목 | 전 | 후 | 위치 |
| --- | --- | --- | --- |
| 단일 기절 11종 | 맞은 적만 | 맞은 곳에서 1.25칸 안의 적 모두. 시간·확률·발동 조건은 그대로 | `stage3/units.json` |
| 발동형 단일 깍 3종 | 맞은 적만 | 맞은 곳에서 1.5칸 안의 적 모두. 수치·시간은 그대로 | `stage3/units.json` |
| 같은 이름표의 깍 | 먼저 건 수치를 남기고 시간은 나중 것으로 덮어씀 | 큰 수치와 긴 남은 시간을 남김. 쌓이는 깍(`maxStacks`)은 그대로 | `logic/src/effects.ts` |

- 기절 11종: 부집게, 쇠망치, 톱, 돈궤, 샅바, 북, 감투 도깨비, 외다리 도깨비, 길달, 씨름 도깨비, 샅바돌개장사. 이미 범위였던 인두판(1칸)·하회탈(1.6칸)·천년 무쇠솥(2칸)은 그대로다.
- 천년 징의 기절은 7초마다 사거리 안 모두를 치는 스킬(`allInRange`)에 붙어 있어 원래부터 사거리 안 모두에게 걸린다. 이 스킬은 반경을 읽지 않으므로 반경을 넣지 않았다. 측정 때는 반경 1.25를 넣었지만 결과에 영향이 없는 값이었다.
- 깍 3종: 숯다리미(마법 12% 3초), 부집게(물리 10% 2초), 약연(마법 15% 3초). 반경은 5등급 범위 깍(기름틀·약탕기·망건)과 같은 1.5칸이다.
- 매 타격 깍 8종은 단일로 둔다: 두두리, 갯불 도깨비, 천년 맷방석, 천년 무쇠솥, 천년 징, 천년 요강, 천년 상모, 쇠밥짐승. 범위로 바꾸면 매 타격마다 범위로 걸리게 되어 "발동할 때만" 조건에 어긋난다. 나중에 보스용 단일 깍 역할로 쓴다.
- 1·2단계 파일에서 오는 유닛(솥뚜껑, 가마솥, 디딜방아, 함지박, 가위, 다듬이방망이, 모루, 기름병, 주마등)은 3단계에도 섞이지만, 고치면 1·2단계 판과 1단계 골든 시험이 바뀌므로 그대로 둔다.
- 보스 기절 상한(`bossControl`)은 그대로라 보스에게는 범위여도 걸리는 양이 같다.
- 유닛 설명은 "주변 1.25칸 스턴 0.75초"처럼 자동으로 칸 수가 붙는다.

이름표 수정 전에는 천년 맷방석(기름틀 이름표, 19% 3초)이 먼저 걸린 적에게 기름틀(30% 12초)이 다시 걸려도 19%에 묶였고, 시간은 매번 나중에 건 쪽으로 덮였다. 1·2단계에는 다른 유닛끼리 이름표를 같이 쓰는 데이터가 없어서 결과가 바뀌지 않는다(같은 유닛이 다시 걸면 수치와 시간이 같다). 3단계 데이터 버전은 바뀌므로, 이전 빌드에서 열린 방과 기록은 지금처럼 그 빌드의 규칙 커밋으로 재생한다.

## 3. 측정

명령(`packages/sim`에서, 시드 1~60, 6인 판 60개 = 자리 360개):

```
npm run sim -- --stage 3 --check grade6 --defeat on --difficulty hard --seeds 60 --out sim-out/aoe-after-hard
npm run sim -- --stage 3 --check grade6 --defeat on --difficulty hell --seeds 60 --out sim-out/aoe-after-hell
```

기준은 `744e3b8`에서 같은 명령으로 쟀다. 반경 1.5·1.75는 임시 데이터로 쟀다. 이 브랜치의 결과 CSV는 측정 때 쓴 임시 데이터(반경 1.25 + 이름표 수정)의 결과와 바이트까지 같다.

### 읽은 내용

- 어려움 완주는 +1.6%p(target), +4.8%p(switch) 올랐다. v7의 "크게 쉬워짐" 기준(완주율 +10%p, 60R 보스 시간 -15%)에는 걸리지 않는다.
- 지옥은 그대로다. target은 50R 전에 자리의 70%가 떨어지고, 팀 결과도 관문(역신) 실패가 가장 많다.
- 65~70R 탈락은 거의 줄지 않았다. 65R부터는 줄에 살아 있는 일반 적이 60마리를 넘는 순간 진다(`limit 60`, `limitInstantFromRound 65`). 기절은 적을 멈추게만 하고 수를 줄이지 않으므로 이 판정에는 거의 영향이 없다. 수를 줄이는 것은 처치 속도뿐이고, 깍은 이미 상한 근처다. 후반을 쉽게 하려면 화력 쪽을 따로 손봐야 한다.
- 이름표 수정만 넣은 판(20판)은 어려움·지옥 모두 기준과 결과가 똑같았다. 봇은 같은 이름표 유닛을 함께 써서 결과가 갈리는 경우가 없었다.

### 잰 것과 못 잰 것

- 쟀다: 어려움·지옥, target·switch 봇, 60판씩. 반경 1.25·1.5·1.75. B안은 20판.
- 못 쟀다: 보통 난이도, 다른 봇(clumsy, normal, synergy), 사람 플레이. 봇은 뭉친 적을 노려 배치하지 않으므로 사람이 배치를 신경 쓰면 효과가 더 클 수 있다.
