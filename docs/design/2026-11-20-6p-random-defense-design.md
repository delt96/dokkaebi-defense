## 1. 의도와 목표

- 왜 **(결정)**: 만드는 재미. 웹에서 링크 하나로 여럿이 같이 놀 수 있는 게임을 직접 만들어 보고 싶다.
- 성격: 취미 프로젝트. 수익화는 목표가 아니다. (사용자 답변에서 추정)
- 재미의 핵심 세 가지 **(결정)**:
    1. 뽑기의 손맛
    2. 어려운 걸 깼을 때의 쾌감
    3. 조합을 잘 짜서 내 라인에 남은 몹 수를 확인하고 서로 공유하는 맛
- 세 가지를 살리는 장치 **(제안)**:
    1. 뽑기: 등급별 연출 차이(빛, 소리, 화면 흔들림), 희귀 등급 등장 시 6명 전원에게 알림, 소환 보정으로 허탕 연속 방지
    2. 고난도 클리어: 난이도 단계를 분명히 나누고 상위 난이도 클리어에 칭호나 기록을 남김. 보스 라운드를 확실한 고비로 설계
    3. 남은 몹 공유: 6개 라인의 남은 몹 수를 항상 띄우는 스코어보드, 라운드 끝 요약, 판 끝 결과 화면을 이미지나 링크로 공유. 랭킹 기준 후보는 "최고 난이도 클리어 + 남은 몹 수"
- 성공 기준 **(제안)**: 6명이 한 판을 끝까지 렉 없이 하고 "한 판 더"가 나온다.
- 진행 방식 **(제안)**: 핵심 게임(소환, 조합, 웨이브, 멀티)을 먼저 완성하고 계정, 매칭, 랭킹은 단계적으로 붙인다. 취미 프로젝트에서 한 번에 다 만들면 끝까지 못 가는 경우가 많기 때문이다.
- 서버 비용 **(제안)**: 무료~월 몇만 원 수준.

## 2. 목표 / 비목표 / 금지선

- 목표 **(결정)**: 모르는 사람끼리도 모여서 할 수 있는 6인 협동 웹게임. 계정, 매칭, 랭킹 포함.
- 매칭 관련 제약: 6인 매칭은 동시 접속자가 있어야 돌아간다.
    - 1~6인 어느 인원으로도 시작할 수 있고 인원수에 따라 공유 보스 체력을 보정한다 **(제안)**. 보정 방식은 7.4 한 곳에서 정한다.
    - 판 도중 합류는 없다 **(결정, 사용자)**. 인원은 시작할 때 고정되고, 이후에는 이탈로만 줄어든다.
- 모바일 **(사용자: 고려해 볼 만함)**: 1단계부터 가로 화면 기준, 터치로 누르기 쉬운 UI 크기, 해상도 대응으로 짠다. 정식 지원 여부는 2단계 이후 실제 기기로 확인하고 정한다.
- 금지선 **(결정)**: 원작(원피스) IP와 원본 맵의 유닛, 이름, 조합표, 수치를 쓰지 않는다. 워크래프트 3 에셋도 쓰지 않는다.

## 4. 세계관과 아트

### 4.1 세계관을 고르는 기준

1. 조합이 이야기 안에서 말이 될 것. 게임 전체가 조합으로 굴러가기 때문이다.
2. 등급 차이를 팔레트 교체, 장신구, 광원 같은 싼 방법으로 표현할 수 있을 것. 유닛 116종(6.1)을 감당해야 한다.
3. 재미의 핵심 세 가지 중 하나 이상을 세계관이 키워 줄 것.
4. 원작을 이름만 바꾼 것처럼 보이지 않을 것. 해적 테마는 이 이유로 뺐다.
5. 몹이 라인을 계속 도는 이유가 세계관에 있을 것.
6. "남은 몹 수"가 세계관 용어로 불릴 것. 친구에게 보낼 때 말이 되어야 한다.

5, 6번은 Fable 서브에이전트가 추가했다. 후보 7개와 비교는 `docs/design/theme-candidates.md`.

### 4.2 세계관: 묵은 물건 도깨비 (결정)

오래 쓴 물건에 도깨비불이 붙으면 도깨비가 된다. 여섯 고개 마을의 헌 물건들이 밤마다 넘어오는 잡귀를 막는다. 게임 제목은 「도깨비 랜덤 디펜스」, 줄여서 도랜디다 (사용자 결정, 2026-11-20). 처음 가제 「묵은 것들」은 뜻이 잘 전해지지 않아 바꿨다.

세부 설정 **(제안)**:

| 게임 요소 | 세계관 안에서 |
| --- | --- |
| 플레이어 6명 | 여섯 고개를 하나씩 맡은 도깨비 주인 (호칭 미정) |
| 소환 토큰 | 도깨비불 한 점. 라운드마다 받음 |
| 랜덤 소환 | 도깨비방망이 "뚝딱". 불꽃 색으로 등급 예고 → 물건 실루엣 공개 |
| 유닛 | 헌 물건 도깨비. 빗자루, 짚신, 솥뚜껑, 장독, 키, 부지깽이, 갓, 엽전 꾸러미 등 한국 생활 물건 |
| 등급 | 불꽃 색 + 불꽃 갈래 수 (뿔은 쓰지 않음, 4.3). 6등급만 큰 도깨비 전신 |
| 조합 | 도깨비불을 한 물건에 몰아 줌. 불이 커질수록 더 오래 묵은 물건이 깨어남. 재료는 결과물의 부품이나 쓰임새로 이어지게 짠다 (예: 짚신 + 새끼줄 → 짚 멍석, 다듬이 + 방망이 → 다듬잇돌) |
| 라인 | 마을로 들어오는 여섯 고개. 잡귀가 서낭당을 탑돌이하듯 돈다 |
| 일반 몹 | 잡귀, 역귀, 그슨대 같은 그림자형. 실루엣 팔레트 교체로 제작 |
| 라운드 보스 | 민담 요괴 (불가사리, 강철이, 지네각시 등) |
| 공유 보스 | 당산나무를 노리는 큰 역신. 단계마다 탈이 바뀜 |
| 남은 몹 수 | "우리 고개 잡귀 N" |
| 탈락 | 고개가 뚫림 |
| 스토리 관문 전원 패배 | 역신이 당산나무에 닿아 당산나무가 쓰러짐 |

- 잡귀가 마을로 바로 들어오지 않고 고개를 도는 이유 **(제안)**: 고개마다 장승이 서 있어 잡귀가 지나가지 못하고 그 앞을 맴돈다. 잡귀가 너무 많이 모이면 장승이 넘어져 고개가 뚫린다. 장승은 고개 끝에 서 있는 배경 소품으로, 잡귀 수에 따라 금이 가는 모습으로 한도 게이지를 대신할 수 있다.

- 분위기 **(제안)**: 유닛은 익살, 세계는 으스스. 물건 도깨비는 동글고 표정이 풍부하게 그려 뽑는 맛을 살린다. 배경은 밤으로 고정하고 도깨비불을 거의 유일한 광원으로 쓴다. 잡귀와 보스는 어둡고 위협적으로 그린다. 사용자는 아직 생각이 없어서 샘플 스프라이트를 보고 다시 판단한다.
- 쓰쿠모가미(일본 물건 요괴)와 겹치는 문제: 물건, 복식, 색을 한국 것으로 잡아 차별점으로 삼는다.
- 정물 공격 동작이 밋밋한 문제: 투사체와 이펙트로 보완한다.
- 미정: 플레이어 호칭, 등급별 불꽃 색 확정, 유닛 목록.

### 4.3 아트 제작 방식 (결정)

| 안 | 방식 | 판단 |
| --- | --- | --- |
| A. 직접 그리기 | Aseprite로 정물 몸통을 그리고 공통 레이어(눈, 불꽃)를 코드로 합성 | **채택**. 화풍 통일, 비용 없음, 시간이 가장 많이 듦 |
| B. AI 초안 + 손질 | PixelLab·Retro Diffusion 초안을 Aseprite로 다듬음 | 미채택. 구독 비용과 약관 확인 부담. AI는 프레임 간 일관성이 아직 약함 |
| C. 에셋팩 구매 | 팩 구매 후 리컬러 | 탈락. 한국 생활 물건 팩이 거의 없어 세계관과 안 맞음 |

- 움직임 **(제안)**: 프레임을 그리지 않고 코드로 만든다. 통통 튀기, 기울이기, 찌그러짐·펴짐(squash & stretch), 공통 눈 깜빡임·불꽃 레이어. 정물 도깨비라서 가능하다.
- 이펙트 **(결정)**: 투사체, 타격, 소환 연출은 Pixel FX Designer로 스프라이트 시트를 만든다.
- 그림 도구 **(결정)**: Aseprite를 소스에서 직접 빌드한다(개인 사용 무료, 실행 파일 재배포 불가). 그 위에 Aseprite MCP를 붙여 Claude가 초안 그리기, 등급별 팔레트 일괄 교체, 스프라이트 시트 내보내기를 돕는다.
    - MCP 후보: MalloyTheDev/aseprite-mcp (Windows 안내와 `claude mcp add` 설치 방법 있음, 커밋 302개) 우선. 대안은 diivi/aseprite-mcp (별 약 1k).
    - 대안 편집기: Pixelorama(무료 오픈소스), Piskel(브라우저). LibreSprite는 MCP와 호환되지 않을 가능성이 높아 제외.
- 미정: 스프라이트 해상도(32px 또는 48px). 샘플 스파이크로 정한다.
- 샘플 스파이크 1차 (2026-11-20, 버리는 작업): `art/samples/`에 솥뚜껑 도깨비(1등급, 파란 불꽃), 빗자루 도깨비(2등급, 초록 불꽃), 잡귀를 32px로 그리고 밤 배경 합성(`night_scene_x6.png`)을 만들었다.
    - 확인된 것: 32px에서도 물건 실루엣과 표정이 읽힌다. 불꽃 색이 밤 배경에서 등급 표시로 잘 보인다. 좌우 대칭 절반 그리기 + 미러 스크립트로 한 종에 몇 분이면 초안이 나온다.
    - 문제: 잡귀가 어두운 몸에 어두운 테두리라 밤 배경에서 가장자리가 흐려진다. 테두리에 보라색 림 라이트나 은은한 발광이 필요하다.
    - 다음 시도 후보: 도깨비 몸에 불꽃 색 반사광, 잡귀 림 라이트, 48px 비교본.
- Fable 검수 (`docs/design/art-review-01.md`): 한국색과 으스스함이 약하고, 쓰쿠모가미 문법(점 눈 + 볼터치)과 겹친다는 지적. 32px 유지, 화면 표시는 2배 권장.
- 공통 아트 규칙 v0 **(제안, 2차 샘플에 적용)**:
    - 등급 표시: 뿔은 쓰지 않는다(일본 오니 이미지). 불꽃 색 + 불꽃 갈래 수(1등급 한 갈래, 2등급 두 갈래 …). 불꽃은 같은 크기 틀(10×9px), 몸 위 1px 띄움, 별도 레이어로 분리 예정.
    - 얼굴: 하회탈식 초승달 눈매와 크게 웃는 입. 점 눈과 볼터치는 쓰지 않는다.
    - 다리 없음. 움직임은 코드로.
    - 몸통 윗면은 불꽃색으로 비춘다. 물건마다 오래 쓴 흔적 하나(땜질, 녹, 끈).
    - 색: 무쇠는 따뜻한 검회색, 짚은 황토, 끈은 쪽빛. 채도 높은 빨강은 잡귀 눈 전용.
    - 잡귀: 검은 외곽선 대신 연보라 테두리 빛, 산발 머리카락, 비대칭 실루엣.
    - 배경: 유닛이 서는 구역은 단색.
- 2차 샘플 (`art/samples/v2/`, `compare_x6.png`에서 1차와 비교): 솥뚜껑은 납작한 돔과 버섯형 꼭지, 빗자루는 휜 솔과 두 갈래 불꽃, 잡귀는 산발 머리와 테두리 빛. 남은 문제는 솥뚜껑 몸통 명도가 아직 낮다는 점.

## 5. 코어 루프

### 5.1 한 판의 길이 (결정)

원본급 깊이를 기본으로 하고, 난이도에 따라 끝나는 라운드를 다르게 한다.

| 난이도 (가칭) | 끝 라운드 | 한 판 (라운드 약 40초 기준) |
| --- | --- | --- |
| 쉬움 | 40 | 약 27분 |
| 보통 | 50 | 약 35분 |
| 어려움 | 60 | 약 42분 |
| 최상위 1~2단계 | 60 + 연장 10라운드 | 약 50분 |

- 표의 숫자는 제안이다. 난이도 단계 수와 이름은 8장과 함께 확정한다.
- 표의 시간은 40초 × 라운드 수만 계산했다. 보스 라운드(제한 약 75초)와 준비 시간이 빠져 있어 실제로는 더 길다. 모르는 6명이 끝까지 남기 어려운 길이라서 첫 6인 플레이판은 20~30라운드(15~20분)로 짧게 만든다 (10.1).
- 판이 길어서 중간 이탈 대응이 필수다: 재접속, 이탈자 라인 처리, 인원 감소 보정 (7장).

### 5.2 라운드 흐름 (제안)

- 원본처럼 타이머로 흐른다. 라운드는 약 40초마다 시작되고, 이전 라운드 잡귀를 다 잡지 못해도 다음 잡귀가 들어온다. 그래서 못 잡은 잡귀가 고개에 쌓이고, 그 수가 "남은 몹 수"가 된다.
- 라운드 시작: 도깨비불 2개 지급 → 라운드 내내 소환·조합·강화·배치 가능 → 잡귀가 시간차로 등장.
- 10라운드마다 고개 보스 라운드. 제한 시간 안에 잡아야 한다 (7.1-1).
- 공유 보스는 스토리 진행용으로 따로 돈다 (7.4).

### 5.3 "남은 몹 수"의 정의 (제안)

재미의 핵심 3번이자 랭킹 기준이라서 숫자가 흔들리지 않게 정한다.

- 라운드 끝 숫자: 라운드가 끝나는 순간 내 고개에 있는 잡귀 수. 스코어보드, 서낭당 정성, 라운드 요약이 이 숫자를 쓴다.
- 판 결과 숫자: 마지막 라운드 끝 숫자와, 판 동안 가장 많았던 순간의 숫자를 함께 보여준다.
- 세지 않는 것: 고개 보스, 미션 요괴, 어둑시니, 공유 보스. 일반 잡귀만 센다.
- 이 숫자를 다른 사람이 바꾸는 규칙은 두지 않는다. 그래서 넋의 "잡귀 직접 태우기"는 빼고(7.2), 따라잡기 보정은 랭킹 판에는 적용하지 않으며(8.2), 도깨비 내기는 초기 범위에서 뺀다(7.5).

## 6. 등급과 조합 체계 (결정, 세부 일부 제안)

### 6.1 최종 조합 목표는 설화 속 유명한 도깨비 (결정, 사용자 아이디어)

최상위 등급(큰 도깨비 전신)을 설화에 나오는 유명한 도깨비로 정하고, 조합표는 그 목표에서 거꾸로 내려오며 짠다. 플레이어가 "비형랑 만들기" 같은 목표를 갖고, 재료 물건이 그 도깨비 이야기와 이어져 조합을 외우지 않아도 짐작할 수 있다.

후보 **(제안, 출처 확인 수준 표기)**:

| 최종 도깨비 | 설화 근거 | 재료 물건 방향 (예) | 확인 |
| --- | --- | --- | --- |
| 비형랑 | 『삼국유사』 도화녀와 비형랑. 귀신들을 부리는 인물 | 다른 큰 도깨비 여럿 (도깨비들의 우두머리) | 확인 |
| 방망이 도깨비 | 도깨비 방망이·혹부리 영감 설화. "금 나와라 뚝딱" | 다듬이방망이, 부지깽이, 엽전 | 확인 |
| 감투 도깨비 | 도깨비 감투 설화. 쓰면 몸이 안 보임 | 갓, 망건, 탕건 | 확인 |
| 김서방 | 김서방 도깨비 설화. 덩치 크고 잘 속음, 풍어신으로 모심. 도깨비가 사람을 "김서방"이라 부른다는 설도 있어 방향이 반대일 수 있음 | 그물, 어망추, 엽전 꾸러미 | 확인 필요 |
| 외다리 도깨비 | 독각귀·양매. 다리가 하나인 도깨비 | 짚신 한 짝, 지팡이 | 확인 |
| 제주 영감 | 제주에서 도깨비를 영감이라 부름, 영감신 | 허벅, 제주 생활 물건 | 확인 |
| 길달 | 『삼국유사』 비형랑조에 나오는 것으로 알려짐 (Fable 기억) | — | 원전 확인 필요 |
| 두두리 | 경주 지역 도깨비신으로 알려짐 | — | 신뢰할 출처 확인 필요 |

- 2016년 드라마 「도깨비」 등 현대 창작물의 캐릭터와 설정은 쓰지 않는다. 설화 원형만 쓴다.
- 위 설화 도깨비는 모두 6등급에 둔다.

- 최종 개수: 6종은 적다는 사용자 지적. 참고로 원본은 전설 위 최상위 5개 등급(제한 11, 신비 13, 초월 9, 불멸 14, 영원 12)만 합쳐 59종이었다. 별도로 계정 귀속 초월 영웅 40종, 히든 26종이 있었다. 다만 전설 위 등급의 공격력은 전설의 1.5~2.5배에 머물렀고, 차이는 대부분 스킬로 냈다. 개수 결정 **(사용자)**: 최종 등급(6등급) 하나만 30종.

- 이 장르는 아래가 좁고 위가 넓은 역피라미드가 맞다. 소환 풀이 작아야 같은 유닛이 겹쳐 조합 재료가 모이고, 조합 결과는 많아야 고를 거리가 생긴다. 원본도 아래부터 9/14/33/44/43(전설)/59(최상위)였다. 앞서 가정한 20/14/10/6/4/2 피라미드는 장르에 맞지 않아 폐기.
- 6등급 30종 구성 **(제안)**: 설화 속 유명한 도깨비 약 10종 + 천년 묵은 물건 대도깨비 약 20종. 물딜 15, 마딜 15. 설화 이름만으로는 30종을 못 채워서 "오래 묵은 물건이 큰 도깨비가 된다"는 세계관 규칙으로 나머지를 채운다.
- 등급별 수 **(결정, 숫자는 밸런스 단계에서 조정 가능)**: 1등급 8 / 2등급 12 / 3등급 18 / 4등급 22 / 5등급 26 / 6등급 30, 합계 116종 + 히든 4~6(보스 길들이기).
- 판당 6등급 목표 **(결정, 사용자)**: 어려움 기준으로 판이 끝날 때 한 사람이 6등급 3~4개를 갖는다. 30종 중 무엇을 만들지 고르는 재미와 물딜·마딜 섞기를 살리면서 하나하나는 귀하게 남기는 숫자다.
- 이 목표에 맞춰 비용을 다시 짠다 (Fable 검토): 지금 6.2 레시피대로면 6등급 하나에 1등급 90~135개가 든다. 6.3 확률로 도깨비불 하나는 1등급 약 1.4개 값이라, 60라운드 120개를 전부 소환에 써도 약 170개다. 이대로면 6등급이 판당 0~1개다. 라운드별 수입 대 등급별 비용 표를 만들어 레시피 재료 수, 도깨비불 지급량, 퀘스트·보스 보상을 3~4개에 맞춘다.
- 소환으로만 나오는 1등급 8종은 각각 물딜 계열과 마딜 계열 레시피 양쪽에 쓰이게 한다. 검증 스크립트 항목에 넣는다.
- 아트 부담 대응 **(제안)**: 1~3등급은 작은 물건 스프라이트(32px, 싸게), 4~5등급은 몸통 틀 + 소품 조합, 6등급은 48px로 크게. 6등급도 몸통 틀을 몇 가지 공유하고 설화 도깨비 10종만 완전 고유 디자인.

### 6.2 조합 방식: 전부 고정 레시피 (결정, 사용자)

검토한 안: A 전부 고정 레시피(채택) / B "같은 등급 3개 → 다음 등급 랜덤" 같은 규칙 기반(짜는 재미가 없어 탈락) / C 아래 등급 규칙 + 위 등급 고정(규칙이 두 종류라 미채택).

- 소환으로만 나오는 유닛을 뺀 모든 유닛에 정해진 레시피가 있다. 약 100개.
- 따라오는 필수 요소 **(제안)**:
    - 조합 도감: 모든 레시피를 판 안팎에서 찾아볼 수 있음
    - 조합 도우미: 지금 가진 유닛으로 만들 수 있는 것, 목표 유닛까지 남은 재료를 보여줌. 고정 레시피 116종을 외우게 만들지 않기 위해서다
    - 조합 도우미를 연 횟수를 센다 **(사용자 아이디어)**: 판 결과 화면에 "도우미 N회"를 표시하고, 0회 클리어에는 칭호를 준다. 랭킹 순위에는 넣지 않는다. 도감을 다른 창에 띄우면 우회되어 실력 지표가 못 되고, 쓰지 말라는 압력이 되면 도우미를 만든 이유와 어긋나기 때문이다 (Fable 검토)
    - 레시피는 JSON 데이터로 관리하고, 검증 스크립트로 확인한다: 모든 유닛이 만들어질 수 있는지, 아무 데도 안 쓰이는 유닛이 없는지, 특정 하위 유닛에 수요가 쏠리지 않는지

레시피 형태 **(제안, 1단계 명세 6.1에서 고침)**:

| 결과 | 재료 | 1등급 값 |
| --- | --- | --- |
| 2등급 | 1등급 2 | 2 |
| 3등급 | 2등급 1 + 1등급 2 | 4 |
| 4등급 | 3등급 1 + 2등급 2 | 8 |
| 5등급 | 4등급 2 + 메밀묵 | 16 |
| 6등급 | 5등급 2 + 특정 3·4등급 1 + 메밀묵 + 엽전 | 36~40 |

- 6등급 설화 도깨비는 설화와 이어진 재료를 요구한다 (예: 감투 도깨비 ← 갓·망건 계열).
- 재료는 단계마다 약 2배로 늘고 위력은 등급마다 2.6배로 뛰어서, 조합하면 항상 이득이 되게 한다. 처음 안(단계마다 약 3배)은 6등급 하나에 1등급 90~135개가 들어 판당 3~4개 목표와 맞지 않았다.

### 6.2-1 유닛 고유 스킬 (결정, 사용자)

- 유닛마다 고유 스킬을 가진다. 등급이 낮을수록 단순하게(공격 시 확률로 스턴·둔화 정도), 높을수록 개성 있게. 6등급 30종은 종마다 확실히 다른 스킬.
- 원본 참고: 전설 위 등급의 공격력은 전설의 1.5~2.5배에 머물렀고 차이는 스킬로 냈다. 흔한 효과는 마법 피해, 스턴, 물리 피해, 방어 깎기, 둔화였고, 발동 확률 10~15%, 스턴 0.9~2.75초, 둔화 15~45%, 오라(방어 −3~−33, 아군 공속 +20~60%)가 있었다.
- 1단계에 스킬을 다 넣지 않더라도 유닛 데이터 구조와 전투 처리는 처음부터 스킬과 상태 이상(스턴, 둔화, 방어 깎기 등)을 전제로 짠다.

### 6.3 소환 (제안)

- 소환 토큰(도깨비불)으로 1~3등급이 나온다. 확률 초안: 1등급 70%, 2등급 25%, 3등급 5%. 원본은 하위 4등급 풀에서 등급 안 균등이었고 히든이 0.24%였다. 히든은 소환에서 나오지 않고 보스 길들이기로만 얻는다 (6.1).
- 소환 보정: 1등급을 7번 뽑을 때마다 그 플레이어가 가장 적게 뽑은 1등급을 준다 (원본 그대로).
- 토큰 용도 선택: 유닛 소환 / 엽전 / 메밀묵 중 고른다 (원본 구조).
- 레시피가 막혔을 때 푸는 수단: 유닛 판매를 둔다. 들인 값의 약 30%를 엽전으로 돌려준다. 메밀묵 환급은 5·6등급부터다 (1단계 명세 7장).

### 6.4 물리 딜과 마법 딜 구분 (결정, 사용자)

유닛마다 물리 딜(물딜)과 마법 딜(마딜) 중 하나를 가진다. 적은 둘 중 한쪽에 강하거나 약하다. 그래서 한쪽으로만 몰아 짜면 막히는 라운드가 생긴다.

세계관 연결 **(제안)**:

- 물딜 = 물건 본체로 때림 (방망이, 솥뚜껑, 다듬이). 마딜 = 도깨비불을 쏨.
- 형체가 흐린 잡귀·그슨대 계열은 물딜을 덜 받는다. 단단한 요괴는 마딜을 덜 받는다.
- 보스 예: 불가사리. 쇠를 먹고 자라고 불로 물리쳤다는 이야기가 널리 알려져 있어, 물딜(쇠붙이)에 강하고 마딜(불)에 약한 보스가 설화와 맞다. 이름 풀이("불로도 죽일 수 없다")와 반대라서 설화 출처를 확인한 뒤 정한다.
- 원본 참고: 공격 타입 3종(일반·관통·공성)과 방어 3종이 가위바위보처럼 맞물렸고, 공격 타입별 업그레이드가 따로 있었다. 이 게임은 2종으로 단순화한다.
- 6등급 30종도 물딜 15, 마딜 15로 나눈다 (6.1).

### 6.5 남은 것

- 레시피 재료 수와 수입의 맞춤 (6.1 비용 확인)
- 판매가, 히든 길들이기 조건 (10.2)

## 7. 6인 협동 구조 (결정, 세부 일부 제안)

### 7.1 패배 조건: 개인 탈락 (결정, 사용자)

검토한 안: A 개인 탈락(채택, 원본 방식) / B 당산나무 공유 체력, 쓰러지면 전원 패배 / C 넘친 잡귀가 당산나무로 몰려가는 섞기.

- 자기 고개의 잡귀가 한도를 넘은 상태가 일정 시간 이어지면 그 사람만 탈락한다 (원본: 70마리 이상 약 6초).
- 따라오는 정할 것 **(제안)**:
    - 클리어 조건: 한 명이라도 끝까지 살아남아 마지막 라운드(또는 최종 보스)를 넘기면 팀 클리어. 탈락자도 결과 화면에 함께 표시
    - 탈락 직전 유닛 양도: 따로 두지 않는다. 양도는 지게 도깨비로만 가능하다는 7.4 결정을 따른다 (빌더 검토에서 발견한 충돌, Claude 판단)
    - 탈락자가 할 일: 7.2에서 결정
    - 판이 27~50분이라 초반 탈락자가 오래 구경만 하는 문제가 남는다. A를 고르면서 생기는 비용이다

### 7.1-1 패배 조건은 세 가지 (결정, 사용자)

| 조건 | 결과 | 원본 |
| --- | --- | --- |
| 내 고개 잡귀가 한도를 넘은 상태가 일정 시간 지속 | 그 사람 탈락 | 70마리 이상 약 6초 |
| 10라운드마다 나오는 고개 보스를 제한 시간 안에 못 잡음 | 그 사람 탈락 | 제한 시간 약 75초 |
| 스토리(공유 보스 단계)를 정해진 라운드까지 정해진 단계만큼 못 밀음 | 전원 패배 | 어려움 이상에서 적용 |

- 고개 보스 실패 탈락은 모든 난이도에 적용한다 **(결정, 사용자)**. 원본 쉬움은 보스를 놓쳐도 탈락하지 않았지만, 이 게임은 쉬움에서도 고개 보스가 확실한 고비가 되게 한다.
- 스토리 관문의 라운드와 단계 기준은 난이도별로 정한다. 쉬움에도 적용할지는 8장 밸런스에서 정한다 **(Claude 판단: 원본은 어려움 이상만 적용)**.
- 그래서 공유 보스는 선택 보상이 아니라 핵심 루프의 일부다. 1~2단계 계획에 스토리 진행 판정이 들어간다.

### 7.2 탈락자는 넋이 되어 지원 (결정, 사용자)

검토한 안: 관전만 / 응원 버프 / 넋으로 지원(채택).

- 탈락자는 도깨비불 넋이 되어 끝까지 판에 남는다. 라운드마다 받는 작은 지원 토큰을 남은 사람에게 보낸다. 잡귀를 직접 태워 없애는 안은 남은 몹 수를 흔들어서 뺐다 (5.3).
- 넋의 역할은 지원 토큰 보내기 하나로 둔다 **(결정, 사용자)**. 검토에서 나온 쉬움·보통 완화, 넋의 공유 보스 지원, 팀 부활은 채택하지 않았다. 초반 탈락자가 오래 넋으로 지내는 비용은 감수한다. 2단계 플레이판에서 실제로 사람들이 나가 버리는지 보고 다시 판단한다.
- 탈락이 벌이 아니게 되지 않도록 지원량은 작게 잡는다 (수치는 8장). 넋 여럿이 한 사람에게 몰아줄 때를 대비해 받는 쪽 상한을 둔다.
- 탈락자의 유닛, 고개의 잡귀, 남은 자원은 원본처럼 모두 없앤다 **(제안)**.
- 클리어 기록에는 끝까지 살아남은 인원을 함께 남기고, 랭킹은 시작 인원별로 나눈다 **(제안)**. 다섯이 탈락해도 기록이 같으면 묻어가기가 생기기 때문이다 (Fable 검토).

### 7.2-1 유닛 배치: 칸 배치 + 칸 사이 이동 (결정, 사용자)

검토한 안: 칸 배치 + 칸 사이 이동(채택, Fable 권고) / 구역 안 자유 배치.

- 고개 옆에 배치 칸이 있고, 유닛은 칸에 하나씩 놓인다. 언제든 다른 빈 칸으로 끌어 옮기거나 두 유닛의 자리를 맞바꿀 수 있다. 유닛을 움직여 사거리를 맞추는 재미를 살린다.
- 잡귀는 정해진 길을 돌기 때문에 유닛이 길목을 몸으로 막지는 않는다 (9.3).
- 다른 고개로는 옮길 수 없다. 칸 수가 곧 고개당 유닛 상한이다 (숫자는 8장).
- 칸이 정해져 있어서 서버는 칸마다 사거리 안에 드는 경로 구간을 미리 계산해 둘 수 있다. 시뮬레이터도 칸 단위로 같은 계산을 쓴다.
- 터치에서는 칸에 맞춰 붙기 때문에 손가락으로도 정확히 놓인다.

### 7.3 중간 이탈 (제안)

- 연결이 끊기면 3분 동안 재접속을 기다린다. 그동안 그 사람의 유닛은 계속 공격하고(유닛은 고정 타워), 받는 토큰은 쌓아 둔다. 소환과 조합만 멈춘다.
- 3분이 지나면 탈락으로 처리하고 넋 상태로 바꾼다. 나중에 돌아오면 넋으로 이어서 참여한다.
- 재접속 대기 중에 고개 보스 라운드가 오면 보스 제한 시간을 판정하지 않고 보스를 다음 라운드로 미룬다. 대기 중에는 잡귀 한도 판정만 한다 **(Claude 판단)**.
- 인원이 줄 때 공유 보스 보정은 7.4를 따른다.

### 7.4 공유 보스, 양도, 인원 보정 (제안, 원본 구조)

- 공유 보스: 당산나무를 노리는 큰 역신, 단계형. 격파하면 전원 보상, 피해 기여도 1위에게 추가 보상.
- 공유 보스 전투 방식 **(결정, 사용자: 여섯 고개를 차례로 돈다)**: 역신 하나가 고개를 하나씩 지나가고, 각 고개의 유닛은 역신이 자기 고개를 지날 때 때린다. 유닛이 자기 고개를 벗어나지 않아도 6명이 한 보스를 같이 잡는다.
- 따라오는 세부 **(제안)**:
    - 한 바퀴에 못 잡으면 처음 고개로 돌아와 다시 돈다. 스토리 관문은 정해진 라운드까지 몇 단계를 잡았는지로 판정한다 (7.1-1).
    - 고개 순서에 따른 유불리: 단계마다 출발 고개를 한 칸씩 돌린다. 앞 고개에서 다 잡혀 뒤 고개가 못 때리는 일이 고르게 나뉜다.
    - 탈락한 사람의 고개는 역신이 빠르게 지나간다. 남은 인원 기준 체력 보정(아래)과 함께 화력 공백을 메운다.
    - 역신은 "남은 몹 수"에 세지 않고 잡귀 한도 판정에도 넣지 않는다 (5.3).
    - 지나가는 동안 그 고개 잡귀와 함께 처리해야 해서, 자기 고개를 지킬 배치와 역신을 때릴 배치 사이의 고민이 생긴다.
- 유닛 양도 **(결정, 사용자: 원본처럼 양도 유닛을 뽑아야 가능)**: 양도가 너무 잦으면 게임이 쉬워지므로 아무나 넘길 수 없다.
    - 원본: 특정 유닛의 능력으로만 양도. 대상은 희귀함 이하, 상대 동의 필요, 동시에 하나만. 주는 쪽 목재 +12, 받는 쪽 +6.
    - 이 게임 **(제안)**: 양도 전용 유닛 "지게 도깨비"(짐을 져 나르는 지게). 소환이나 뽑기 장터에서 낮은 확률로 나온다. 능력으로 4등급 이하 유닛 하나를 다른 사람에게 보낸다. 상대 동의 필요, 쿨타임 있음. 양쪽 모두 메밀묵 보상.
- 1~6인 보정 **(제안, 2장과 7.3을 이쪽으로 통합)**: 공유 보스 체력은 살아 있는 인원수에 비례한다. 판 중 탈락·이탈로 인원이 줄면 그 순간부터 남은 인원 기준으로 다시 계산한다. 원본의 "1명당 −10%"는 화력이 6분의 1씩 빠지는 것에 비해 보정이 작아서, 한 명 탈락이 스토리 관문 전원 패배로 번지기 쉽다 (Fable 검토). 라인 몬스터는 라인마다 독립이라 보정하지 않는다.
- 1~2인 판: 팀 퀘스트 기준은 인원수에 맞춰 줄이고(8.2), 양도와 기여도 1위 보상은 1인 판에서 끈다.

### 7.5 퀘스트 (결정: 넣는다, 사용자 / 구성은 제안)

원본에는 개인 미션(구매형 60초 보스, 실패 시 다음 2라운드 토큰 없음), 스토리(공유 보스 13단계), 게이트, 보물찾기(팀 합계 20개면 전원 보상), 도전과제 약 12종(예: 8라운드 전 희귀함 제작 → 선택 위습)이 있었다.

| 종류 | 내용 | 보상 | 원본 대응 |
| --- | --- | --- | --- |
| 개인 미션 | 엽전으로 시작권을 사면 내 고개에 미션 요괴가 나옴. 제한 시간 안에 잡기 | 엽전, 메밀묵. 실패하면 시작권 값만 잃음 (원본의 토큰 몰수는 퀘스트가 필수인 어려움 이상에서 실패가 실패를 불러 뺌, Fable 검토) | 미션 |
| 도전과제 | 판마다 1회성 목표 (예: 10라운드 전 4등급 만들기, 물딜·마딜 각각 5등급 보유) | 도깨비불, 메밀묵 | 도전과제 |
| 팀 퀘스트 | 6명이 같이 채우는 목표 (예: 고개마다 숨은 도깨비 감투 조각 찾기, 합계 N개) | 전원 보상 | 보물찾기 |
| 설화 퀘스트 | 6등급 설화 도깨비와 이어진 이야기 목표. 예: 혹부리 영감 퀘스트를 깨면 방망이 도깨비 재료인 "도깨비 방망이"를 얻음 | 6등급 조합 재료 | 없음 (새로 추가) |

- 설화 퀘스트는 6등급 레시피와 묶어서, 설화 도깨비를 만드는 과정 자체가 이야기가 되게 한다.

추가 퀘스트 후보 **(제안, 사용자가 추가를 허락함)**:

| 이름 | 종류 | 내용 | 보상 | 키우는 재미 |
| --- | --- | --- | --- | --- |
| 도깨비 씨름 | 돌발 이벤트 | 떠돌이 도깨비가 무작위 한 명에게 씨름을 건다. 20초 안에 씨름 도깨비의 체력을 깎아 넘어뜨리면 승리. 밤길 씨름 설화에서 따옴 | 승리 시 메밀묵, 낮은 확률로 지게 도깨비 | 어려운 걸 깸 |
| 서낭당 정성 | 팀 퀘스트 | 라운드가 끝날 때 여섯 고개 잡귀 합계가 기준 이하이면 성공. 3회 연속 성공하면 큰 보상 | 전원 도깨비불 | 남은 몹 공유 |
| 도깨비 내기 (보류) | 개인 도박 | 라운드 시작 전 엽전을 걸고 "이번 라운드 끝에 내 고개 잡귀 N 이하"를 선언. 성공하면 2배. 게임이 기준을 제시하면 기대값이 0이거나 수입 인플레가 되어 초기 범위에서 뺀다 (Fable 검토) | 엽전 | 남은 몹 공유, 뽑기 |
| 도깨비 시장 | 시간 한정 상점 | 몇 라운드마다 한 라운드 동안만 열리는 장. 희귀 뽑기, 지게 도깨비 확률 상승 | 상점 | 뽑기 |
| 어둑시니 | 위험과 보상 | 한 고개에 작은 그림자가 나타나 시간이 갈수록 커진다. 일찍 잡으면 작은 보상, 내버려 두면 그 고개의 미니 보스가 된다. 어둑시니 설화는 출처 확인 필요 | 크기에 비례한 보상 | 어려운 걸 깸 |
| 메밀묵 잔치 | 팀 퀘스트 | 6명이 메밀묵을 모아 잔치를 열면 몇 라운드 동안 전원 버프 | 팀 버프 | 협동 |
| 도감 채우기 | 계정 단위 | 판 밖에서 이어지는 기록. 만든 유닛·설화 도깨비·깬 난이도를 도감에 남기고 칭호를 준다 | 칭호 | 어려운 걸 깸, 공유 |

- 출시 범위 **(제안)**: 개인 미션, 도전과제, 서낭당 정성, 도깨비 씨름을 먼저 넣는다. 설화 퀘스트는 6등급과 같이, 도감 채우기는 계정 기능과 같이 붙인다. 나머지는 이후 업데이트.

## 8. 경제와 밸런스 곡선 (논의 중)

### 8.1 자원 (제안)

| 자원 | 세계관 | 원본 대응 | 얻는 곳 | 쓰는 곳 |
| --- | --- | --- | --- | --- |
| 엽전 | 기본 화폐 | 골드 | 잡귀 처치(고정 1냥, 원본은 확률형), 라운드 보상 | 강화, 6등급 조합, 뽑기 장터 |
| 도깨비불 | 소환 토큰 | 위습 | 라운드마다 2개 | 소환, 또는 엽전·메밀묵으로 바꿈 |
| 메밀묵 | 희소 자원. 도깨비가 메밀묵을 좋아한다는 설화에서 | 목재 | 고개 보스, 미션 보스, 공유 보스, 5·6등급 판매, 양도 | 5·6등급 조합, 일부 뽑기 |

- 뽑기 장터 (제안): 엽전으로 랜덤 유닛이나 자원을 뽑는 상점. 원본의 도박 상점(250~3,500골드, 성공률 17~85%)에 해당하며 "뽑기의 손맛"을 판 중반 이후까지 잇는다.
- 메밀묵 설화 근거는 확인 필요.

### 8.2 퀘스트와 밸런스 (사용자 우려, 원칙은 제안)

퀘스트 보상이 쌓이면 수입이 부풀고, 잘하는 사람이 더 받아 격차가 벌어진다. 아래 원칙으로 막는다.

| 위험 | 원칙 |
| --- | --- |
| 수입 인플레 | 라운드별 "기대 수입" 총량을 먼저 정하고, 퀘스트 보상은 그 안의 몫(예: 25%)으로 배분한다. 퀘스트를 더해서 수입이 늘어나는 구조가 아니라, 퀘스트를 안 하면 그 몫을 못 받는 구조 |
| 빈부 격차·눈덩이 | 개인 보상에는 판당 상한을 둔다. 큰 보상은 팀 퀘스트(전원 지급)로 몰아준다. 뒤처진 사람에게 미션 보상을 조금 더 주는 따라잡기 보정은 일부러 뒤처지는 쪽이 유리해질 수 있어 랭킹 판에는 적용하지 않는다 (5.3) |
| 이른 보상의 복리 | 퀘스트마다 열리는 라운드를 정한다 (원본: 미션 15라운드 해금, 31·40라운드에 일부 판매 종료). 메밀묵처럼 상위 조합을 앞당기는 보상은 늦게 연다 |
| 필수 숙제화 | 난이도별 역할을 정한다 (8.3에서 결정) |
| 악용 | 도깨비 내기: 기준 잡귀 수를 플레이어가 아니라 게임이 그 사람의 현재 처리량을 보고 제시. 확실히 이기는 내기를 막는다. 어둑시니: 일부러 키워서 보상만 챙기지 못하게 보상 상한 |
| 인원 차이 | 팀 퀘스트 기준은 살아 있는 인원수에 맞춰 조정 |

### 8.3 퀘스트의 난이도별 역할 (결정, 사용자)

검토한 안: A 전부 보너스 / B 난이도에 따라(채택) / C 전부 필수.

- 쉬움·보통: 퀘스트를 안 해도 클리어할 수 있다.
- 어려움 이상: 퀘스트를 챙겨야 클리어할 수 있다. "퀘스트까지 챙겨서 깼다"가 실력이 된다.
- 시뮬레이션 기준: 쉬움·보통은 "퀘스트 안 함"으로 클리어 가능, 어려움 이상은 "절반 수행"으로 아슬아슬, "전부 수행"으로 여유.

검증 방법 **(제안)**: 밸런스 수치를 JSON으로 빼고, 라운드별 적 체력 대비 기대 화력·수입을 계산하는 시뮬레이션 스크립트를 만든다. "퀘스트 전부 수행 / 절반 / 안 함" 세 경우를 돌려 난이도별 클리어 가능 여부를 본다. 서버 게임 로직을 화면 없이 돌릴 수 있게 짜면 봇 대전으로도 확인할 수 있다.

논의할 것: 자원 종류(원본은 골드 + 목재 + 토큰), 수입 구조, 적 체력 곡선, 아군 화력 곡선. 원본의 숫자 인플레(적 HP 135→1,600만)는 피한다.

## 9. 기술 구성 (결정)

### 9.1 접근 방식

| 안 | 방식 | 판단 |
| --- | --- | --- |
| A. 서버 판정 + 브라우저 렌더 | Node.js 서버가 게임 규칙을 전부 계산, 브라우저는 결과를 받아 그림 | **채택 (사용자)**. 조작 방지, 재접속, 믿을 수 있는 랭킹, 화면 없는 시뮬레이션이 한 구조로 해결됨. 판마다 서버 계산 비용이 듦 |
| B. 락스텝 | 서버는 입력만 전달, 6명의 브라우저가 같은 계산 | 탈락. 서버 비용은 가장 싸지만 계산 어긋남(부동소수점), 조작 방지, 재접속이 어려워 랭킹 게임에 맞지 않음 |
| C. 엔진 웹 내보내기 (Godot 등) | 엔진 편집기로 만들어 웹으로 내보냄 | 탈락. 웹 빌드 수십 MB로 "링크 하나로 바로 놀기"와 어긋나고, 멀티 서버는 결국 따로 필요 |

### 9.2 구성

| 영역 | 선택 | 이유 |
| --- | --- | --- |
| 언어 | TypeScript (클라이언트·서버·시뮬레이터 공통) | 레시피, 유닛 데이터, 규칙 코드를 한 벌로 공유 |
| 렌더링 | Phaser | 트윈(통통 튀기, squash & stretch), 입력, 사운드, 씬 관리 기본 제공. 2D 탑뷰, 화면 2배 정수 확대 |
| 멀티 서버 | Node.js + Colyseus | 방 생성, 상태 동기화, 재접속 지원 내장. 서버 권위형 |
| 게임 로직 | 렌더링과 분리된 순수 TypeScript 모듈 | 같은 코드를 서버, 밸런스 시뮬레이터, 봇 대전에서 그대로 실행 |
| 데이터 | 유닛·레시피·밸런스 수치를 JSON으로 | 검증 스크립트와 시뮬레이터가 읽음 (6.2, 8.2) |
| 이펙트 | Pixel FX Designer | 4.3 |
| 그림 | Aseprite(소스 빌드) + Aseprite MCP | 4.3 |
| 계정·랭킹 저장소 | 미정, 후속 단계에서 결정 | 1단계 범위 밖 |

### 9.3 동기화 원칙 (제안)

- 잡귀는 정해진 길을 돈다. 위치를 매 틱 보내지 않고 등장 시각, 속도, 경로 번호만 보내 브라우저가 위치를 계산한다. 체력 변화와 처치는 이벤트로 보낸다.
- 둔화·스턴처럼 속도가 바뀌면 그 순간의 경로상 위치와 새 속도를 이벤트로 보낸다. 브라우저는 그 시점부터 다시 계산한다.
- 소환·조합·양도·구매는 클라이언트가 요청만 보내고 서버가 판정한다. 랜덤(소환 결과)은 서버에서만 굴린다.
- 부하 기준: 이 게임은 라운드마다 고개당 30마리가 나오고 한도가 60마리다(1단계 명세, 원본은 35와 70). 한도 직전까지 쌓이면 60마리 × 6고개 = 동시 최대 약 360마리, 넉넉히 420마리로 잡는다. 투사체는 서버가 판정 결과만 보내고, 투사체 비행은 브라우저 연출로 처리한다.

## 10. 단계, 미정 사항, 빌더 재량

### 10.1 단계 (제안, 1장 "핵심 게임 먼저" 원칙)

1. 1단계, 1인 프로토타입: 상세는 `2026-11-20-stage1-spec.md`. 한 고개 20라운드(약 15분), 칸 배치와 칸 사이 이동, 소환, 고정 레시피 조합(1~4등급 22종), 고개 보스 2번, 잡귀 한도·보스 실패 패배 판정, 스킬 효과 11가지, 강화. 게임 로직 모듈과 JSON 데이터 구조를 이때 확정한다. 화면 없이 로직을 돌리는 밸런스 시뮬레이터도 이때 만든다. 3단계 수치를 잡으려면 먼저 있어야 하기 때문이다 (Fable 검토).
2. 2단계, 첫 6인 플레이판: Colyseus 방, 방 링크 초대와 임시 닉네임, 6개 고개, 남은 몹 스코어보드, 탈락과 넋 지원, 재접속, 공유 보스(스토리)와 스토리 관문 패배 판정. 1~4등급 40종 안팎, 20~30라운드(15~20분). 여기서 "한 판 더"가 나오는지 확인한 뒤 다음으로 간다.
3. 3단계, 콘텐츠: 5·6등급과 설화 도깨비, 유닛 고유 스킬 확장, 퀘스트(우선 4종), 지게 도깨비 양도, 뽑기 장터, 판 길이를 5.1 목표까지 늘림.
4. 4단계, 밸런스: 시뮬레이터 확장과 봇 대전으로 난이도별 수치 조정 (8.2, 8.3).
5. 5단계, 서비스: 계정, 공개 매칭(1~6인 시작), 랭킹(시작 인원별), 도감, 결과 공유. 공개 매칭은 동시 접속자가 모인 뒤에 붙인다.
6. 모바일: 6개 고개 스코어보드와 끌어 옮기기를 작은 화면에 함께 넣기 어렵다. 1단계에서는 UI 크기를 터치 가능하게 잡는 정도만 하고, 정식 대응은 2단계 이후 실제 기기로 보고 정한다.

### 10.1-1 콘텐츠 제작 방식 (결정, 사용자)

- 116종 유닛 목록, 레시피, 스킬, 수치 초안은 Claude가 만들고 Fable 서브에이전트가 검토한다. 사용자가 최종 확인한다.
- 그림도 같은 방식: Claude가 Aseprite MCP로 초안, Fable 검수, 사용자가 다듬거나 확정.
- 1단계는 임시 유닛 몇 종과 `art/samples/` 스프라이트로 시작해도 된다. 콘텐츠 작업과 코드 작업은 나란히 진행한다.

### 10.2 아직 정하지 않은 것

- 플레이어 호칭, 등급별 불꽃 색 6개 확정, 116종 유닛 목록과 레시피 전체
- 난이도 단계 수와 이름, 라운드별 적 체력·화력·수입 곡선의 실제 숫자
- 강화(업그레이드) 체계: 사용자는 "다양하게"를 원함. 1단계 안은 1단계 명세 8장. 3단계에서 뚝딱 강화·장승 강화 등 갈래를 더할지 다시 본다
- 히든 유닛(보스 길들이기)의 얻는 조건
- 계정·랭킹 저장소와 호스팅
- 적 쪽 물량 집계: 잡귀 종류 수, 고개 보스 4~6종, 공유 보스 단계 수(원본 13)와 단계별 탈, 미션 요괴. 유닛 쪽만큼 일이 크다 (Fable 검토)
- 설화 출처 확인: 길달, 두두리, 김서방, 불가사리, 어둑시니, 메밀묵
