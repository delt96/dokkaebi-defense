# 인크리멘탈: '힘들던 게 쉬워지는' 쾌감 설계 노트

작성일: 2026-11-20 · 출처: 서브에이전트(Fable, max) 자문 요약. [정설]은 장르에서 널리 확인된 것, [추측]은 가설이다. 수치는 전부 출발점이다.

## 핵심 진단
- 쾌감은 "숫자가 커진다"가 아니라 "같은 일 한 단위에 드는 수고가 줄어든다"다.
- 밸런스 지표는 초당 생산량이 아니라 단위당 입력 횟수(손), 필요한 정밀도(눈), 대기 시간(시간)으로 잡는다.

## 원칙 (영향 큰 순)
1. **고정 잣대.** 같은 단위, 고정된 골대(예: "주문 1건 = 20개")를 끝까지 유지해 첫 5분 → 20초 → 자동 처리의 대비가 느껴지게 한다. 레이어마다 화폐를 갈아치우지 않는다. 숫자는 묶음 단위로 올린다. (Paperclips, Antimatter Dimensions의 무한) [정설]
2. **초반 노동은 손기술.**
   - 진행도가 작업물 표면에 보여야 한다.
   - 첫 쉬워짐은 숙련에서 온다(첫 개 15–20초, 다섯 번째 8초).
   - 일감은 끝이 보이는 더미로 준다.
   - 첫 구매 90초 안, 낱개 구간 약 5분, 첫 조수 10–15분.
   - 다음 해방 하나만 효과가 적힌 가격표로 보인다("넓은 솔: 30번 → 12번").
   - 가끔 3배 힘든 '미운 놈'을 낸다.
3. **해방 사다리, 숫자가 아니라 동사를 바꾼다.**
   - 단계: 도구 → 관대함 → 누르고 끌기 → 일괄 → 조수(나보다 느림) → 추월 → 추상화(한 줄로 접힘).
   - 단계당 최소 2배 개선. 구매 직후 1초 안에 새 도구를 써 보게 한다.
   - "내 손 기여도 100% → 0.02%"를 표시한다.
4. **병목 이동.** 한 공정이 자동화되면 다음 공정이 새 손일이 된다. 손일은 항상 1–2개이고 나머지는 눈앞에서 저절로 돈다. 새 손일은 다른 동작이어야 하며, 1인 개발이면 3–4개가 현실적이다. 관리 계층도 같다(구매 클릭 → 최대 구매 → 자동 구매). [정설]
5. **톱니 리듬.**
   - 잔돌(10–30%)은 30–90초마다, 돌파(동사 변경 또는 5배 이상, 연출 동반)는 8–20분마다.
   - 돌파 직후 1–3분간 구매가 연쇄로 풀린다.
   - 벽 앞에서 순수하게 기다리는 시간은 2–3분 이내.
6. **대비를 직접 보여준다.**
   - 0분부터 기록한다("첫 주문 5:12 / 지금 0:03").
   - 줌아웃: 손 → 작업대 → 공방 → 공장.
   - 자동화를 내 손의 복제로 그린다.
   - 필요 없어진 패널은 치운다.
   - 손 소리가 겹쳐 기계 리듬이 된다.
   - 엔딩의 마지막 1개는 손으로 만든다.
7. **프레스티지는 압축.**
   - 1레이어, 첫 리셋 50–70분, 총 3–5회.
   - 리셋 후 이전 정점까지 5–10배 빨라야 한다.
   - 보상은 배율보다 초반 자동화와 시작 장비.
   - 고스트 스플릿("지난 회차 31:20 / 이번 2:45").
   - 3–5시간 게임에 2레이어 이상은 과하다.
   - 대안: "2호점"(1호점은 계속 돌고 새 지점을 맨손으로 시작).
8. **자동화는 노동의 결과물.**
   - 직접 100개를 하면 조수가 열리는 식으로 연다.
   - 귀찮은 것부터 자동화하고, 손맛 있는 동작은 가장 늦게 자동화한다.
   - 플레이테스트 중 "귀찮다" 싶은 시각에서 30–60초 뒤 그 귀찮음을 없애는 업그레이드가 열리게 가격을 맞춘다.

## 페이싱 (4시간 기준, 추측)

| 시점 | 사건 |
|---|---|
| 0–2분 | 맨손 수작업, 숙련으로 15초 → 8초 |
| 1.5–5분 | 첫 도구, 첫 주문 기록 |
| 5–12분 | 끌기, 일괄, 두 번째 공정 등장 |
| 10–20분 | 첫 조수, 20분경 추월 |
| 20–45분 | 공정 3단계, 병목 2회 이동, 30분경 첫 줌아웃 |
| 45–70분 | 의도된 벽, 리셋 예고, 첫 리셋 |
| 70–80분 | 8–10분 만에 이전 정점, 새 메커닉 |
| 80–150분 | 리셋 2–3회, 손일에서 배치·배분 결정으로, 120분경 두 번째 줌아웃. 처지기 쉬운 구간이라 장르 전환급 변화 1개 필요 |
| 150–210분 | 리셋 졸업, 폭주 구간 |
| 210–240분 | 유한한 최종 목표, 마지막 1개는 손으로, 통계 화면 |

- 엔딩은 넣기를 권한다. 잣대를 지키고, 1인 개발자가 반복 테스트할 수 있다.

## 오프라인과 세이브
- **해방은 접속 중에.** 오프라인 중 자동 구매·자동 리셋은 없다.
- **병목 제한 오프라인.** 자동화된 공정만 돌고, 수작업 병목 앞 버퍼가 차면 멈춘다.
- **후반 상한.** 전부 자동화된 뒤에는 2–8시간 상한을 둔다.
- **복귀 보고.** 대비 장치로 쓴다("처음 손 속도로는 13시간 분량").
- **시간 계산.** 틱 횟수가 아니라 실제 경과 시간으로 계산하고, 숨겨진 탭과 오프라인을 같은 코드 경로로 처리한다.
- **저장.** 자동저장(10–30초, 구매 시, 탭 숨김 시), 버전 필드와 마이그레이션, 내보내기/가져오기 문자열. 기록과 스플릿 데이터도 세이브에 포함한다.

## 실패 유형
1. 수입과 비용이 같이 올라 체감 수고가 그대로인 러닝머신
2. 노동 생략(30초 만에 자동화) 또는 과잉(같은 수고가 2–3분 넘게 변화 없음)
3. 눈에 안 띄는 해방(미세 누적, 오프라인 지급)
4. 전부 자동화된 뒤의 공허
5. 고생만 돌려주는 리셋
6. 수동 연타가 끝까지 최적이라 손목이 아프고 오토클리커가 등장
7. 레이어와 화폐 과다
8. UI 버튼 벽
9. 개별 파티클과 소리가 스케일하지 않아 렉과 소음
10. 노동이 힘든 구간에 UI 마찰까지 겹침

## 주제 선정 기준
- 진행도가 작업물 표면에 드러나는 손작업
- 끝까지 셀 수 있고 묶음으로 올릴 수 있는 단위
- 동작이 서로 다른 3–4단계 공정
- 손 → 작업대 → 공방 → 그 이상으로 이어지는 줌아웃 단계
