# 70라운드 개편 설계 (2026-11-23)

## 왜 하는가

사용자 요청: 라운드당 시간을 줄이고, 70라운드까지 늘려서 후반 몹을 세게. 처음 대기 시간도 길다.
한 판 길이는 지금(약 44분)과 비슷하게 둔다(사용자 결정).

## 정한 것 (사용자 결정)

- 1~60라운드의 내용과 이벤트 위치는 그대로 두고, 61~70을 마지막 구간으로 붙인다.
- 몹은 **65라운드부터** 눈에 띄게 세진다.
- **65라운드에 5번째 역신**을 넣는다.

## 검토한 방식

1. **61~70을 뒤에 붙이기 (사용자 선택):** 기존 이벤트(장터·사냥·역신 1~4·씨름·그림자)는 원래 라운드에 그대로 둔다. 지금까지 맞춘 밸런스가 덜 흔들린다.
2. 모든 이벤트를 7/6배 뒤로 옮기기: 보스가 12·23·35…라운드가 되고, 모든 이벤트를 다시 맞춰야 한다. 얻는 게 적다.
3. 1번 + 새 몹·새 그림: 가장 다채롭지만 그림과 스킬을 새로 만들어야 한다. 이번에는 하지 않는다.

## 시간 (내 판단)

| | 지금 | 바꾼 뒤 |
|---|---|---|
| 처음 대기 `prepSeconds` | 30초 | 15초 |
| 일반 라운드 `roundSeconds` | 40초 × 54 | 34초 × 63 |
| 보스 라운드 `bossRoundSeconds` | 75초 × 6 | 70초 × 7 |
| 합계 | 2,640초(44분) | 2,647초(약 44분) |

- 몹 30마리가 0.8초 간격으로 나오는 데 24초가 걸리므로, 34초면 다 나온 뒤 10초가 남는다(지금 16초). 생성 간격은 그대로 둔다.
- 라운드가 짧아지면 처음부터 압박이 커진다. 시뮬레이터로 초반 기준(아래)이 깨지지 않는지 본다. 깨지면 일반 라운드를 35초로 하고 보스를 65초로 줄이는 쪽(약 44.6분)을 먼저 시도한다.
- 역신 체류 시간(`staySeconds` 12초), 사냥 시간 같은 초 단위 값은 그대로 둔다.

## 61~70라운드 내용

- **웨이브 61~69:** 기존 몹만 쓴다. 51~59의 패턴 순서를 이어 쓴다.
- **70라운드 최종 보스:** 지네각시와 강철이가 번갈아 나오는 차례대로 `jinegaksi7`(이름 '지네각시', 기존 그림을 그대로 씀. `sprites.ts`가 숫자를 떼고 찾는다). 체력은 시뮬레이터로 정한다. 출발값은 지금 보스 체력이 오르는 폭(10라운드마다 +25,000)에 65라운드 강화를 더한 값이다.
- **65라운드 강화 (내 판단: 방법):** 적 체력 공식 `base + coef × r^exp`에 65라운드부터 배수를 곱한다. 균형 데이터에 `hp.late: { fromRound: 65, perRound: x }`를 두고 배수는 `1 + x × (r − 64)`로 계산한다. 출발값 x = 0.08이면 R65는 ×1.08, R70은 ×1.48이다. 최종값은 시뮬레이터로 정한다. 61~64는 지금 공식 그대로 이어진다.
- **저항:** `resistByRound`가 R60에 0.45로 끝나는데, `toRound 70, top 0.55`로 늘린다. R60 값이 0.44로 지금과 거의 같고, 그 뒤로 조금씩 더 오른다. 상한 0.8은 그대로 둔다.

## 5번째 역신

- `coop.json`에 5단계를 추가한다: 적 `yeoksin5`('역신 다섯째 탈'), 65~69라운드, 시작 자리 `startIndex: 4`. 처치 보상과 1등 보너스는 기존 역신과 같다.
- 체력(`baseHp`): 역신 4가 210,000이다. 시너지 봇 기준 처치 시간이 제한의 50~80%가 되도록 시뮬레이터로 정한다. 출발값은 330,000이다.
- 그림은 기존 역신 그림을 그대로 쓴다(숫자를 뗀 `yeoksin`).
- 화면 문구: `online/models.ts`의 단계 이름에 '다섯째'를 더한다. 관문 표시 '관문 N/5'는 데이터에서 세므로 자동으로 맞는다.
- 역신은 협동(온라인) 전용이다. 솔로에는 지금처럼 나오지 않는다.

## 60을 전제한 코드 정리

- `validate.ts`의 `rounds === 60` / `!== 60` 세 곳과 `econ/gamble.ts:9`는 사실상 '3단계 데이터인가'를 묻는다. 라운드 수 대신 그 뜻을 직접 묻게 바꾼다(방법은 만드는 사람에게 맡긴다).
- 클라이언트 `?rounds=60` 주소는 3단계를 여는 표시다. `rounds=70`을 새 표준으로 하고, 이미 퍼진 `rounds=60` 링크도 계속 3단계를 연다.
- '60-round' 주석과 문구를 '70라운드'로 고친다(로비·대기실 안내 포함).
- 시뮬레이터: `econRun.ts`의 `BOSS_ROUNDS`에 70을 더하고, 60을 전제한 집계를 데이터의 라운드 수로 바꾼다.
- 시험: `data-stage3.test.ts` 등 라운드 값을 박아 둔 시험을 새 값으로 고친다.

## 밸런스 기준

`docs/balance/stage3-economy-pass.md`의 기준 1~7은 그대로 지킨다. 6등급 수는 지금과 비교할 수 있게 60라운드 시작 시점으로 센다(70라운드 시점 값도 같이 적는다).

기준 1의 '팀 클리어 95% 이상'과 '패배 켬 완주 80% 이상'은 아래 값으로 바꾼다.

추가 기준:
- 61~64라운드의 탈락은 지금 56~60라운드와 비슷한 수준이다.
- 65~70라운드에서 실제로 탈락이 생긴다. 시너지 봇 팀 클리어는 **55~65%**로 내려온다(사용자: 80~90%는 너무 높다. 값은 내 판단). 전환 봇의 탈락은 절반 이상이 61라운드 이후에 나온다.
- 역신 5의 처치 시간도 기준 7(제한의 50~80%)을 따른다.

## 최종값 (2026-11-23 시뮬레이터로 확정, 측정은 `docs/balance/stage3-economy-pass.md` 17장)

- 시간: 대기 15초, 일반 34초, **보스 75초**(70초에서 되돌림). 한 판 약 44.7분.
- 1~60 화력 유지: 일반 몹 체력 `base` 75 → 63.75, `coef` 16 → 13.6, 역신 1~4 체력 ×0.85(6,800 / 25,500 / 92,650 / 178,500). 라운드가 짧아진 만큼 체력을 낮춰 초당 필요한 화력을 예전과 같게 했다. 시간만 줄이면 역신 관문 시간도 15% 줄어 1~60이 크게 어려워진다.
- 65라운드 배수: `perRound` 0.4(R65 ×1.4, R70 ×3.4). 0.08로는 61~70에 일반 몹 때문에 탈락하는 자리가 없었다.
- 역신 5: 185,000. 최종 보스 지네각시 7: 140,000.
- 결과: 전환 봇 팀 클리어 14/20(목표 55~65%보다 조금 높음, 20시드 노이즈 안). 가장 잘하는 봇은 지금 main에서도 시너지 봇이 아니라 전환 봇이라 전환 봇으로 판정했다.

## 하지 않는 것

- 새 몹 종류, 새 그림, 새 이벤트.
- 1~60 경제 이벤트 위치 변경. 라운드마다 주는 도깨비불·장터 횟수는 61~70에도 그대로 이어진다.
- 20라운드 판(1·2단계 데이터).

## 배포할 때 주의

데이터가 바뀌면 `dataVersion`이 바뀐다. 옛 클라이언트는 새 서버의 방에 들어가지 못하므로 서버와 클라이언트를 함께 배포한다.

## 만드는 사람에게 맡기는 것

`hp.late`의 정확한 이름과 모양, 3단계 판별 방법, 시뮬레이터 실행 시드 수. 수치(x, 보스·역신 체력, 시간)는 위 출발값에서 시작해 기준에 맞춘다.
