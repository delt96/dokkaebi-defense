# UX 수정 묶음 설계 (2026-11-23)

## 왜 하는가

개발할 때 브라우저로 화면을 보지 못해서, 실제로 그려진 화면을 누구도 점검하지 않았다. 2026-11-23 전체 UI 점검(`.impeccable/critique/2026-11-23T03-57-55Z__packages-client-src-ui.md`)에서 사용성 점수가 20/40이 나왔다. 이 문서는 그중 지금 모양 안에서 고칠 수 있는 항목(수정)을 다룬다. 화면을 새로 짜야 하는 항목(개편: 장터 재구성, 정보 창이 보드를 가리는 문제, 솔로·온라인 화면 통일)은 Codex가 맡는다.

가장 큰 문제는 조합 정보가 전부 글자라는 점이다. 보드에서는 유닛을 그림으로 보는데, 조합 목록에서는 이름을 읽고 머릿속에서 그림과 짝지어야 한다.

## 목표와 범위

- 조합 줄에 유닛 그림을 넣는다(유닛 패널, 상세 창, 조합 도우미, 도감, 재료 트리).
- 한 번 눌러 되돌릴 수 없는 판매·길들이기에 한 번 더 확인을 둔다.
- 단축키와 용어를 화면에서 알 수 있게 한다.
- 도감 줄을 읽기 쉽게 정리한다.
- 솔로에서 도감을 여는 동안 시간을 멈춘다.
- 자잘한 겹침과 솔로에 보이는 협동 전용 퀘스트를 정리한다.

**하지 않는 것**
- 장터 화면 구성: Codex 개편으로 넘긴다.
- 도감을 드로어로 바꾸기, 솔로·온라인 카드 통일: 이후 Codex 개편으로 넘긴다.
- 게임 규칙과 데이터: 바꾸지 않는다. 클라이언트 화면만 손댄다(`packages/client`).
- G(1·2등급 모두 보관): 사용자가 규칙을 정하는 중이다. 정해지면 따로 넣는다.

**실패로 보는 것:** 조합 목록에서 한 번에 보이는 정보가 지금보다 줄어드는 것, 단축키 조작이 지금보다 느려지는 것.

## 조합 줄 그림: 고른 방식

목업: `docs/design/mockups/2026-11-23-recipe-images.html`

검토한 방식은 셋이다.
- A. 한 줄 칩 `[Z] [결과 그림] 화로 = [재료][재료]`: 지금처럼 4줄이 보이지만, 재료 이름은 마우스를 올리거나 상세 창에서만 보인다.
- **B. 두 줄 (사용자 선택):** 첫 줄은 `[Z] [결과 그림] 화로 마`, 둘째 줄은 재료 칩과 그 밑에 이름. 처음 하는 사람도 재료 이름을 바로 본다. 한 화면에 보이는 줄은 줄어든다.
- C. 글자 앞에 작은 그림만: 가장 적게 바꾸지만, 바로 할 수 있는 조합의 재료는 여전히 안 보인다.

B로 정했다. 적용 범위는 다음과 같다.
- **유닛 패널 '다음 조합'(솔로 왼쪽 패널):** B. 보이는 줄이 줄어드는 만큼 목록은 지금처럼 따로 스크롤되고, '+N개 더'는 상세 창을 연다.
- **상세 창(Tab) 조합 섹션:** B.
- **조합 도우미(Q):** 등급 점 대신 결과 그림, 재료 칩 + 이름(B와 같은 두 줄), '조합' 버튼은 그대로.
- **도감:** 이름 칸에 결과 그림. 재료 칸은 글자 링크 대신 칩 + 이름. 칩을 누르면 지금처럼 그 유닛 줄로 간다.
- **재료 트리:** 등급 점 대신 작은 칩. ✓/✗ 표시는 그대로.
- **온라인 하단 카드(높이 44px):** 두 줄이 들어가지 않으므로 이번에는 결과 그림만 넣는다(재료 칩은 개편 때).

칩 규칙
- 그림은 `unitFaceHtml`(storage.ts)과 같은 스프라이트를 쓰고, 테두리는 등급 색이다.
- 보드나 보관함에 있는 재료는 실선 테두리와 ✓, 없는 재료는 빨간 점선 테두리에 흐리게 + ✗.
- 같은 재료가 두 개 필요하면 칩을 두 번 그린다(레시피 재료 목록 그대로).
- 5·6등급 비용(메밀묵·엽전)은 칩 줄 끝에 글자로 붙인다.

이를 위해 `CombineOption`에 재료 목록(id, 이름, 등급, 있음 여부)을 더한다. 지금은 없는 재료 이름만 들고 있다.

## 되돌릴 수 없는 키

- **S 판매 (내 판단):** 3등급 이상은 두 번 누르기. 처음 누르면 판매 버튼이 '한 번 더 누르면 판매 +N냥'으로 바뀌고 2초 안에 다시 누르면 판다. 1·2등급은 지금처럼 바로 판다. 마우스로 판매 버튼을 누를 때도 같다.
- **T 길들이기 (내 판단):** 같은 두 번 누르기. 처음 누르면 '30냥 · 성공 N% · T 한 번 더'를 보여 준다. 비용과 확률은 지금 데이터에서 읽는다.
- **보관함:** 숨긴 스크롤바(`scrollbar-width: none`)를 얇게 보이게 해서 아래에 더 있다는 것을 알린다.

## 단축키와 표시

- 하단 도움말을 상황에 따라 바꾼다.
  - 유닛을 고르지 않았을 때: 지금 줄 + Q 도우미, J 퀘스트, (솔로) P 멈춤.
  - 유닛을 골랐을 때: Z/X/C 조합 · S 판매 · R 지게 · Tab 상세 · Esc 선택 해제.
- 보드 유닛의 '조합 가능' 표시(오른쪽 위 2px 노란 점)를 더 크게, 은은하게 깜빡이게 바꾼다(LaneScene). 등급 점은 그대로.
- 장승 게이지는 막대 옆에 상태 글자를 같이 쓴다(지금은 툴팁에만 있음).

## 용어 (내 판단, 문구는 바뀔 수 있음)

- 도감 역할 칩(물깎·마깎·둔화·기절·광역·오라): 도감 위에 한 줄 범례를 둔다. 예: '물깎 = 받는 물리 피해 증가'.
- 공격 유형 배지: 같은 화면 안에서 '물/마'와 '물딜/마딜'이 섞이지 않게, 좁은 곳은 '물/마', 넓은 곳은 '물딜/마딜'로 자리마다 한 가지로 맞춘다.
- '고정' 버튼 → '목표로' / '목표 해제'.
- '불 바꾸기 (+25냥)' → '불 1개 → 25냥'.
- 유닛 패널의 '보유 지게 N개' 옆에 짧은 설명(같은 등급 다른 유닛으로 바꾸는 표).

## 도감 줄 정리

- 이름 칸에 결과 그림(위).
- 능력·메모는 첫 줄만 보이고 '더보기'로 펼친다.
- 재료 트리 범례 '✓ 보드에 있음' → '✓ 보드·보관함에 있음'. 실제 판정이 보관함까지 포함하기 때문이다.
- 왼쪽 필터 칸 폭을 줄여 목록 칸을 넓힌다.

## 솔로 도감 자동 멈춤

- 솔로에서 도감이 열려 있는 동안 시간을 멈추고, 상단에 '멈춤'을 표시한다(`renderHud`의 기존 멈춤 표시를 쓴다).
- 상세·강화·퀘스트 창은 멈추지 않는다. 이 창들에서 누른 조합·강화는 시간이 흘러야 반영되는 구조라(`driver.ts`의 명령은 다음 틱에 처리), 멈추면 창을 닫을 때까지 반영되지 않기 때문이다.
- 사용자가 P로 멈춘 상태는 도감을 닫아도 그대로 둔다. 자동 멈춤은 P와 따로 관리한다.
- 온라인은 그대로다.

## 자잘한 것

- 길들이기 '다시 시도 N초'·'체력 N%' 라벨이 보스 체력바와 겹치지 않게 위치를 옮긴다.
- 온라인 상단 첫 줄 글자가 화면 끝에 닿아 잘리는 것을 고친다.
- 솔로 퀘스트 목록에서 '협동 전용' 퀘스트를 숨긴다.
- 로비·대기실·결과 화면이 확대되지 않아 큰 모니터에서 작게 보이는 문제: 보드와 같은 확대 배율을 적용한다. 구조가 생각보다 크게 바뀌면 개편 쪽으로 넘긴다.

## 확인 방법

- 바뀐 화면 모델 함수는 기존 클라이언트 시험(`packages/client/test`, happy-dom)에 시험을 더한다.
- 실제 화면은 브라우저로 솔로 1~11라운드를 돌려 각 화면을 확대 배율 1·2에서 본다.
- 전체 시험과 `npm run typecheck`가 통과해야 한다.

## 만드는 사람에게 맡기는 것

칩 크기와 간격의 세부값, 두 번 누르기 안내 문구, 깜빡임 속도, 범례 문구. 단, 확대 배율 1(640×360)에서 글자와 칩이 잘리지 않아야 한다.
