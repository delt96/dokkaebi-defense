# 3스테이지 아이템 장터 설계 (2026-11-25)

목업: `docs/design/mockups/2026-11-25-item-shop.html`
측정 근거: `docs/balance/stage3-economy-pass.md` 23~24절

## 왜

- 처음에는 모든 유닛 사거리를 +0.5 올리는 강화를 만들었다. 측정해 보니 사는 쪽과 안 사는 쪽이 비슷해지는 값이 1,800냥 안팎이었다(24절). 그보다 싸면 누구나 사야 하는 강화가 된다.
- 사용자가 고른 방향: 장터에서 아이템을 사서 **유닛 하나를 강화하는 느낌**을 준다. 어느 유닛에 무엇을 붙일지 고르는 재미가 핵심이다.

## 목표 / 하지 않을 것 / 실패로 볼 것

- 목표
  - 3스테이지 장터에 아이템 탭을 둔다. 엽전으로 사서 들고 있다가 유닛 하나에 붙인다.
  - 아이템 값은 봇 측정으로 정한다.
- 하지 않을 것
  - 1·2스테이지에는 넣지 않는다.
  - 스킬형 아이템(맞으면 기절 같은 것)은 넣지 않는다(B안, 나중에).
  - 메밀묵으로 사는 아이템은 없다.
- 실패로 볼 것
  - 아이템 하나가 판을 결정해서 누구나 같은 아이템을 같은 유닛에 붙이게 되는 것(전체 사거리 강화의 실패와 같은 모양).
  - 1·2스테이지 동작이나 골든 해시가 바뀌는 것.

## 정한 것 (사용자)

- 장터에서 사서 **들고 있다가** 유닛에 붙인다. 지게처럼 동작한다.
- **유닛 하나에 아이템 하나.**
- 붙인 유닛을 **조합 재료로 쓰거나, 팔거나, 지게로 바꾸면 아이템이 사라진다.** 칸을 옮기면 따라간다.
- **사거리 부적은 한 판에 한 번**만 산다.
- 만드는 방식은 **A. 수치형 아이템**(아래 '방식').
- 깎기 유닛 4종 범위 + 양 + 지속(23.5)은 이미 데이터에 들어갔다(2453e98). 그대로 둔다.

## 방식

| 안 | 내용 | 득실 | 결정 |
| --- | --- | --- | --- |
| A. 수치형 | 유닛에 아이템 칸 하나. 사거리·공격력·공격 속도를 계산하는 곳에서 아이템 값을 더한다. 약화만 공격할 때 한 줄을 더 건다. | 고칠 곳이 좁고 시험·측정이 쉽다. 스킬형 아이템은 그때마다 한 줄씩 더해야 한다. | **골랐다** |
| B. 스킬형 | 붙이면 유닛에 스킬이 하나 더 생긴다. | 어떤 효과든 된다. 대신 스킬을 유닛 종류에서 읽는 곳을 모두 고쳐야 해서 넓고 위험하다. | 나중에 |
| C. 바로 사서 붙이기 | 장터 없이 유닛 칸에서 산다. | 가장 간단하다. 대신 "장터에서 사서" 붙이는 흐름이 아니다. | 안 함 |

## 제가 정한 것 (고칠 수 있음)

- **바꿔 끼우기:** 이미 아이템이 붙은 유닛에 다른 아이템을 붙이면 옛 아이템은 사라진다. 돌려받으면 아이템을 옮겨 다는 길이 생겨 "조합하면 사라짐"이 의미가 없어진다.
- 사거리 부적 말고는 **몇 번이든 산다.** 유닛 하나에 하나뿐이라 저절로 제한된다.
- **여는 때:** 장터와 같다(`market.openAfterBossRound`, 지금 10R 보스를 잡거나 길들인 뒤).
- **보관함:** 1·2등급 유닛을 보관함에 넣어도 아이템은 유닛에 붙은 채로 남는다. 보관함 유닛은 공격하지 않으니 효과도 없다.
- **준비 시간에도 산다:** 장터 도박은 준비 시간에 막히지만(`marketClosed`), 아이템은 라운드 몫이 없는 물건이라 준비 시간에도 사고 붙인다. 막는 조건은 장터 잠김(10R 보스 전)뿐이다.
- **장터 탭:** 장터 서랍 위에 [뽑기] [아이템] 탭을 둔다. [뽑기]는 지금 장터 그대로다.
- **이름과 첫 수치** (측정 뒤 바꿀 수 있음)

  | id | 이름 | 효과 (붙은 유닛 하나) | 한 판 제한 |
  | --- | --- | --- | --- |
  | `rangeCharm` | 사거리 부적 | 사거리 +0.5 | 1번 |
  | `powerCharm` | 힘 부적 | 공격력 +20% | 없음 |
  | `swiftCharm` | 날쌘 부적 | 공격 속도 +15% | 없음 |
  | `weakCharm` | 약화 부적 | 때린 적이 받는 피해(그 유닛의 피해 종류) +10%, 3초 | 없음 |

- **값 정하는 규칙:** 아이템마다 봇이 사서 붙이게 하고 값을 바꿔 가며 잰다(24절과 같은 방법). 사는 쪽과 안 사는 쪽이 비슷해지는 값의 **절반**을 값으로 제안한다. 사면 이득이지만 엽전이 실제로 아프게 하려는 것이다. 마지막 값은 사용자가 정한다.

## 만드는 법 (빌더 몫이 아닌 것)

### 데이터 (`packages/logic/data/stage3/economy.json`)

`shop` 항목을 더한다. 1·2스테이지에는 `economy`가 없으니 상점도 없다.

```json
"shop": {
  "items": [
    { "id": "rangeCharm", "name": "사거리 부적", "coins": 300, "perGame": 1, "effect": { "kind": "range", "amount": 0.5 } },
    { "id": "powerCharm", "name": "힘 부적", "coins": 150, "effect": { "kind": "attack", "pct": 0.2 } },
    { "id": "swiftCharm", "name": "날쌘 부적", "coins": 150, "effect": { "kind": "speed", "pct": 0.15 } },
    { "id": "weakCharm", "name": "약화 부적", "coins": 150, "effect": { "kind": "vuln", "pct": 0.1, "seconds": 3 } }
  ]
}
```

`coins`는 측정 전 임시값이었다. 측정(`docs/balance/stage3-economy-pass.md` 27절) 뒤 사용자가 **사거리 400 · 힘 150 · 날쌘 120 · 약화 180냥**으로 정했다(2026-11-26, `278c844`). 다섯째 아이템 진화부적(묵 1 + 60냥, 20R부터)은 `2026-11-25-evolve-charm-design.md`. `validate.ts`가 id 중복, 0 이하 값, 알 수 없는 `kind`를 막는다.

### 상태

- `Unit.item?: string`: 붙은 아이템 id. 없으면 키 자체가 없다(해시 보존).
- `EconState.items?: Record<string, number>`: 들고 있는 개수.
- `EconState.itemsBought?: Record<string, number>`: 산 횟수(`perGame` 검사용).
- 둘 다 처음 살 때 생긴다.
- 조합·판매·지게는 새 `Unit`을 만들거나 지우므로, 따로 지우지 않아도 아이템이 사라진다. 시험으로 확인한다.
- **아이템이 붙은 유닛은 재료로 나중에 쓴다 (사용자가 정함).**
  - 조합(`combine.ts`, 지금은 뒤쪽 칸부터 고름)은 같은 유닛이 여럿이면 아이템이 없는 쪽을 먼저 쓴다. 아이템이 붙은 유닛이 남은 유일한 재료일 때만 그것을 쓴다.
  - 그런 조합이면 조합 후보(유닛 칸·도우미 목록)에 "아이템이 사라집니다"를 띄운다.
  - 보관함 꺼내기·보관함 판매(`retrieve`, `sellStored`, 지금은 같은 종류 중 가장 새것)도 아이템이 없는 쪽을 먼저 고른다.
  - 판 위 유닛을 직접 고르는 판매·지게는 플레이어가 고른 그 유닛이다.
  - 아이템이 없는 판에서는 고르는 순서가 지금과 같아야 한다(골든 해시).

### 명령 (`registerCommand`, 장터 명령과 같은 자리)

- `{ type: 'buyItem', item }`. 거절 이유:
  - 상점 없음: `unknown`
  - 장터 잠김: `marketLocked`
  - 한 판 제한을 넘음: 새 이유 `itemLimit`
  - 엽전 모자람: `noCoins`
  - 성공하면 엽전이 빠지고 `items[item]++`, `itemsBought[item]++`
- `{ type: 'attachItem', item, slot }`. 거절 이유:
  - 빈 칸: 기존 빈 칸 이유
  - 들고 있지 않음: 새 이유 `noItem`
  - 성공하면 `items[item]--`, `unit.item = item`(옛 아이템은 사라짐)
- 온라인: `match/parse.ts`에 두 명령을 더한다. `attachItem`은 `move`·`sell`처럼 `unitId`를 실어 보내 다른 유닛에 붙는 일을 막는다. `toWire`가 `unitId`를 채운다.
- 이벤트: `itemBought`, `itemAttached`(효과음·알림용). 이름은 기존 이벤트 관례를 따른다.

### 계산에 더하는 곳

- 사거리: 지금 브랜치의 `unitRange(state, def)`를 `unitRange(state, slot)`로 바꾼다(유닛의 아이템을 읽어야 함). 지금 쓰는 곳(`combat.ts` `pickTarget`, `effects.ts` 오라 깎기·`allInRange` 주기 공격, 클라이언트 사거리 원·효과 그리기·유닛 카드)을 모두 바꾼다.
  - 서는 자리(가장자리/안쪽, `units.ts` `wantEdge`, 봇 `isMelee`, 클라이언트 근접 판단)는 계속 유닛 종류의 `range`로 정한다.
- 공격력: `damageBonus`에 아이템 `pct`를 더한다. 오라 상한(`auraCaps.attackPower`)은 오라에만 걸고, 아이템은 상한 밖이다.
- 공격 속도: `speedBonus`에 아이템 `pct`를 더한다. 오라 상한은 오라에만 건다.
- 약화: 붙은 유닛이 기본 공격으로 맞힐 때마다 **그 공격의 대상 한 마리에게만** 약화를 건다 (사용자가 정함: 단일).
  - 거는 곳은 `performAttack` 끝, `applyPackage` 다음이다.
  - 스킬이 낸 피해에는 걸지 않는다. 주변 피해(splash), 관통, 연쇄, 지속 피해(dot), 바닥 불, 폭발, 주기 공격(`runPeriodics`/`allInRange`), 처치 폭발이 그것이다.
  - 스킬 약화의 `radius`/`area`도 따르지 않는다.
  - 스킬까지 걸면 범위 유닛에서 무리 전체가 약화돼 밸런스가 무너진다.
  - 열쇠는 피해 종류마다 하나다(`item:weakCharm:physical`, `item:weakCharm:magical`). 같은 종류끼리는 겹치지 않는다(같은 유닛 여러 기가 겹치지 않는 지금 규칙과 같다). 물딜 유닛과 마딜 유닛에 하나씩 붙이면 둘 다 듣는다. (제 판단: `applyStatus`는 있던 약화의 피해 종류를 유지하므로, 열쇠 하나로 두면 먼저 맞힌 종류만 남는다.)
  - `vulnCap`을 따른다.
  - 부적 약화는 `vulnCaster`를 세우지 않는다. 그래서 `onVulnKillExplode`(약화된 적 처치 폭발)를 켜지 않는다. 유닛 자신의 스킬이 건 약화만 켠다. (제 판단)
  - `applyStatus`를 거치지 않고 따로 건다. 아니면 위 두 규칙을 `applyStatus`에 예외로 둔다. 어느 쪽이든 빌더 몫이다.

### 화면 (목업 번호)

1. 장터 서랍 [뽑기] [아이템] 탭. 상점이 없는 판에서는 탭이 없다.
2. 아이템 목록: 이름, 효과 한 줄, 값, [사기]. 모자라면 흐리게 하고 모자란 냥을 보여 준다. 한 판 제한을 다 쓰면 "삼".
3. 들고 있는 아이템 개수 줄.
4. 유닛 칸 아이템 줄: 붙은 아이템 이름, 들고 있는 아이템마다 [붙이기]. 이미 붙어 있으면 "붙이면 지금 아이템은 사라집니다".
5. 능력치에 아이템 몫을 붙인다(`사거리 3.5칸 (+0.5 사거리 부적)`, 공격력·간격도 같음). 사거리 원도 넓어진다.
6. 판 위 칸 귀퉁이에 아이템 첫 글자(사·힘·날·약). 다른 고개(온라인 남의 판)에도 보인다. 그래서 `UnitView`에 `item?`을 싣는다.
7. 온라인 아래 한 줄 카드에는 [아이템 ▾] 하나. 누르면 작은 목록이 열린다.

- 단축키는 새로 두지 않는다.
- 도움말 줄·도감은 바꾸지 않는다.

### 봇과 값 재기

- `EconPolicy.item?: string`: 잴 아이템 **한 종류**. (제 판단)
  - 봇은 6등급을 손에 넣으면 공격력이 가장 센 6등급 하나에 붙인다. 6등급 조합 예약금을 뺀 엽전으로 사며, 다른 강화보다 먼저다.
  - 붙은 유닛이 사라지면 다시 사서 다음으로 센 6등급에 붙인다(사거리 부적은 한 번뿐이라 다시 사지 못한다).
  - 그래서 잰 값은 "주력 6등급 하나에 늘 그 아이템이 붙어 있는 값어치"다.
- `scripts/shred-variants.ts`를 넓히거나 새 스크립트로, 아이템 하나씩 값을 바꿔 60시드 × 봇 3종으로 잰다.
  - 측정값: 60R 보스 처치, 70R 도달, 클리어.
  - 기준선(아이템 안 삼)도 같은 코드로 다시 잰다.
  - **사는 쪽과 안 사는 쪽이 같아지는 값:** 봇 3종 클리어의 합으로 본다. 60R 보스 처치 합도 함께 보고, 둘이 다르면 값의 범위로 보고한다. 값은 150냥 간격부터 재고, 같아지는 곳 근처에서 더 촘촘히 잰다. (제 판단)
  - **한 아이템이 판을 결정하는지:** 아이템별 결과를 한 표에 나란히 둔다. 사거리 부적은 붙인 유닛의 사거리(2.0 / 2.5 / 3.0 …)별로도 나눠 본다. 닿는 길이 늘어나는 비율이 사거리마다 ×1.45~×2.03로 다르기 때문이다(24절). 여러 아이템·여러 유닛을 겨루는 측정은 하지 않는다. 마지막 판단은 사용자가 값을 정할 때 한다. (제 판단)
  - 결과는 `docs/balance/stage3-economy-pass.md` 27절에 적고, 값을 데이터에 넣는다(25절은 진화부적이 먼저 썼다). 세분 측정은 하지 않았고 150냥 간격 값 사이를 직선으로 이어 같아지는 값을 구했다.

### 시험

- logic
  - 사기: 값만큼 엽전이 빠짐, 잠김, 한 판 제한, 모자람.
  - 붙이기: 없는 아이템, 빈 칸, 바꿔 끼우면 옛 것이 사라짐.
  - 사라짐: 조합, 판매, 지게. 옮기면 따라감.
  - 네 효과가 각각 사거리·공격력·공격 간격·약화를 바꿈.
  - 1·2스테이지에 상점 없음.
  - 골든 해시 그대로.
  - `parse` 두 명령.
- client
  - 장터 아이템 탭 모델, 유닛 칸 아이템 줄, 능력치 표시, 판 위 표시 모델.
- sim
  - 봇이 목표 6등급에 붙임, 정책이 없으면 사지 않음.

### 화면 다듬기 (2026-11-26, 브라우저 확인 뒤 사용자 결정)

- 화면 4 (솔로 아이템 줄): 들고 있는 종류마다 단추를 두면 폭 118px에 4종부터 이름이 잘리고 5종(길들인 유닛 + 진화부적)이면 마지막 단추가 가려졌다. 줄은 `[힘] 힘 부적  [붙이기 ▾ N]` 한 줄로 두고, 단추를 누르면 온라인 [아이템 ▾]와 같은 목록이 줄 위로 열린다(전체 이름, 개수, "붙이면 지금 아이템은 사라집니다"를 글자로). Esc가 먼저 닫고, 붙이기 거절은 이 단추 위에 뜬다.
- 조합 줄의 "아이템이 사라집니다"는 줄 폭(100px)에 들어가지 않아 잘렸다. 사라질 부적의 첫 글자를 주황 꼬리표 `· −힘`으로 보이고, 이름은 title과 읽기 문구("조합하면 사라지는 아이템: 힘 부적")에 둔다. 로직 `combineEatenItems`가 사라질 아이템 id를 돌려준다. 보관함 조합 단추도 같다.
- 온라인 목록·경고·이름표 글자를 10px, 목록 단추를 24px로 올렸다(B줄 배율 1 기준). 아무것도 들고 있지 않으면 목록에 "장터(B) 아이템 탭에서 삽니다".
- 개발용 점프(`?dev=jump`)가 장터 여는 보스 라운드를 넘기면 장터를 연다(건너뛴 보스를 잡은 것으로 본다). 화면 확인용이고 실제 판에는 영향이 없다.
