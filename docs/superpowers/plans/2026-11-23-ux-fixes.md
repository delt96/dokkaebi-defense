# UX 수정 묶음 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 조합 줄에 유닛 그림 칩을 넣고, 판매·길들이기에 두 번 누르기를 두고, 단축키·용어·도감·솔로 멈춤·자잘한 겹침을 고친다.

**Architecture:** 화면 모델(`ui/models.ts`)의 `CombineOption`·`HelperItem`에 재료 목록을 더하고, 칩 HTML은 새 파일 `ui/chips.ts` 한 곳에서 만든다. 두 번 누르기는 순수 모듈 `ui/confirm.ts`가 판정하고 `mount.ts`가 쓴다. 규칙·데이터(`packages/logic`)는 건드리지 않는다.

**Tech Stack:** TypeScript, DOM 템플릿 문자열, Phaser 3.90, vitest + happy-dom.

**Spec:** `docs/superpowers/specs/2026-11-23-ux-fixes-design.md`

## Global Constraints

- 클라이언트(`packages/client`)만 바꾼다. 게임 규칙과 데이터는 바꾸지 않는다.
- G(1·2등급 모두 보관) 동작은 바꾸지 않는다.
- 확대 배율 1(640×360)에서 글자와 칩이 잘리지 않아야 한다.
- 화면 문구는 한국어, 말하듯 쓴다. 코드 주석은 영어, 코드에서 알 수 없는 것만.
- 실패로 보는 것: 조합 목록에서 한 번에 보이는 정보가 줄어드는 것, 단축키 조작이 느려지는 것.

## Review Focus

- 같은 재료 두 개 레시피(솥뚜껑 ×2)에서 하나만 있을 때: 첫 칩 ✓, 둘째 칩 ✗ (Task 1 시험).
- 그림 파일이 없는 유닛: 칩이 등급 원판 글자로 대신 나온다 (Task 1 시험).
- 1·2등급 판매는 지금처럼 한 번에 팔린다 — 확인이 끼어들면 단축키가 느려진다 (Task 4 시험).
- 2초가 지난 뒤 두 번째 누름은 다시 '처음 누름'으로 본다 (Task 4 시험).
- 사용자가 P로 멈춘 상태에서 도감을 열고 닫아도 멈춤이 풀리지 않는다 (Task 6 시험).
