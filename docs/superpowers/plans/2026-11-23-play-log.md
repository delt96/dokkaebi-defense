# 판 기록 로그 구현 계획

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 온라인·솔로 판이 끝날 때 다시 돌릴 수 있는 판 기록과 요약을 서버 로그에 JSON으로 남긴다.

**Architecture:** 솔로는 `GameDriver`가 틱마다 `step`에 넘긴 명령을 모으고, 판이 끝나면 `solo.ts`가 `POST /api/solo-log`로 보낸다. 서버의 `playLog.ts`는 요약 한 줄과 gzip + base64로 줄인 기록 줄들을 만든다. 온라인은 `RoomCore`가 결과를 낼 때 같은 함수로 찍는다. 서버는 기록을 다시 돌리지 않는다(이벤트 루프를 막지 않기 위해).

**Tech Stack:** TypeScript, vitest(happy-dom), express 5, node:zlib

**Spec:** `docs/superpowers/specs/2026-11-23-play-log-design.md`

## Global Constraints

- 브랜치 `play-log`. 커밋은 하고, push와 main 병합은 하지 않는다.
- 이름이나 식별 정보는 넣지 않는다. 판 id는 무작위다.
- 줄 형식: `[판 기록] <id> <요약 json>`, `[판 기록 데이터 i/n] <id> <base64 조각>`. 조각은 8,000자 이하다.
- 솔로 본문 상한은 1MB이고, `text/plain`으로 보낸다(개발 중 5173 → 2567 사전 요청을 피하려고).
- 연습판(`devJumpTick`)은 남기지 않는다.
- 주석은 영어로, 코드만 봐서 알 수 없는 것만 단다.

## Review Focus

1. 솔로 판을 다시 시작하면(`driver.reset`) 이전 판 기록이 섞이지 않는다. → Task 1 시험
2. 멈춤(P, 도감) 중에는 틱이 없으니 기록도 없다. 멈춤을 풀고 나서 다시 돌려도 같은 결과가 나온다. → Task 1 시험
3. 잘못된 본문(JSON 아님, 1MB 초과, 모양 틀림)이 와도 서버가 죽지 않고 400/413을 돌려준다. → Task 2 시험
4. 조각을 나눈 기록이 원래 기록으로 정확히 돌아온다. → Task 2 시험
5. 솔로 전송이 실패해도(서버 꺼짐) 게임 화면에는 영향이 없다. → Task 3 시험

### Task 1: 솔로 명령 기록과 `replayGame`

**Files:**
- Create: `packages/logic/src/replayGame.ts` (export via `index.ts`)
- Modify: `packages/client/src/driver.ts` (`GameDriver`)
- Test: `packages/client/test/solo-record.test.ts`

**Interfaces:**
- Produces: `interface SoloLogEntry { tick: number; commands: Command[] }`
- Produces: `replayGame(data: GameData, seed: number, difficulty: Difficulty | undefined, log: SoloLogEntry[], maxTicks?: number): GameState`. 로그가 끝나도 판이 끝날 때까지(또는 `maxTicks`) 빈 명령으로 계속 돈다.
- Produces: `GameDriver.record: SoloLogEntry[]`. 명령이 있는 틱만 들어간다. `reset`에서 비운다.
- Produces: `GameDriver.onFinished(cb: (state: GameState) => void)`. 판이 `ended`가 되는 틱에 한 번 부른다.

- [ ] Step 1: 실패하는 시험
  - 드라이버로 stage3 판을 만든다. 소환·전환 명령을 몇 틱에 걸쳐 `queue`하고 `update`로 1,000틱쯤 돌린다. 그런 다음 `replayGame(data, seed, difficulty, driver.record, driver.state.tick)`의 `stateHash`가 `stateHash(driver.state)`와 같다.
  - 중간에 `paused = true`로 `update`해도 기록이 늘지 않고, 결과 해시도 같다.
  - `reset` 뒤에는 `record`가 빈 배열이다.
  - `onFinished`는 판이 끝나는 틱에 한 번만 불린다. 시험용 데이터로 빨리 끝나는 판을 쓴다.
- [ ] Step 2: 실패 확인 → Step 3: 구현 → Step 4: `npx vitest run packages/client/test/solo-record.test.ts packages/logic`로 통과 확인
- [ ] Step 5: 커밋 `Record solo commands per tick and replay them`

### Task 2: 서버 로그 줄과 `/api/solo-log`

**Files:**
- Create: `packages/server/src/playLog.ts`
- Modify: `packages/server/src/server.ts` (경로), `packages/server/src/core/RoomCore.ts:330-338` (결과 때 기록)
- Test: `packages/server/test/play-log.test.ts` (기존 파일에 더함)

**Interfaces:**
- Produces: `playLogLines(id: string, summary: object, record: unknown): string[]`, `readPlayLog(lines: string[]): { id: string; summary: unknown; record: unknown }[]`
- Produces: `parseSoloLog(body: string): SoloLogBody | null`. 모양 검사: `stage` ∈ stage1·stage3, `seed` 정수, `difficulty`는 없거나 난이도 값, `dataVersion` 문자열, `log`는 `{tick: 정수, commands: 배열}`의 배열, `summary`는 객체다.
- 온라인 요약: `{ mode: 'online', stage, difficulty, players, outcome, round, minutes, dataVersion, rulesRevision, seats: [{ seat, outcome, round, board: defId[], storage: defId[] }] }`

- [ ] Step 1: 실패하는 시험
  - `readPlayLog(playLogLines(id, s, big))`가 원래 값과 같다. 기록이 커서 데이터 줄이 2줄 이상인 경우도 확인한다.
  - 모든 줄이 8,200자 이하다.
  - 온라인 판이 끝나면 `deps.log`에 `[판 기록] `로 시작하는 줄이 생기고, 요약의 `seats[i].board`에 그 자리 유닛 id가 있다. 이름 문자열은 줄 어디에도 없다.
  - `devJumpTick` 판은 `[판 기록]` 줄이 없다.
  - `parseSoloLog`는 JSON이 아닌 본문, 모양이 틀린 본문에 null을 돌려준다.
  - 경로 시험: 정상 본문은 204를 돌려주고 로그 줄이 생긴다. 깨진 본문은 400이고, 1MB 초과는 413이다(express 기본).
- [ ] Step 2: 실패 확인 → Step 3: 구현(`node:zlib` `gzipSync`, `crypto.randomUUID`) → Step 4: `npx vitest run packages/server`로 통과 확인
- [ ] Step 5: 커밋 `Log finished matches and solo games as replayable records`

### Task 3: 솔로가 판 끝에 보내기

**Files:**
- Create: `packages/client/src/soloLog.ts`
- Modify: `packages/client/src/solo.ts`
- Test: `packages/client/test/solo-log.test.ts`

**Interfaces:**
- Consumes: Task 1의 `GameDriver.record`·`onFinished`, Task 2의 본문 모양
- Produces: `soloLogBody(state: GameState, seed: number, difficulty: Difficulty | undefined, stage: 'stage1' | 'stage3', record: SoloLogEntry[]): SoloLogBody`. 요약은 `{ mode: 'solo', stage, difficulty, outcome, round, minutes, board: defId[], storage: defId[] }`다.
- Produces: `sendSoloLog(body: SoloLogBody, post?: typeof fetch): Promise<void>`. 실패해도 던지지 않는다.

- [ ] Step 1: 실패하는 시험
  - 끝난 판 상태로 만든 본문이 Task 2의 `parseSoloLog`를 통과한다. 클라이언트 시험에서 server 패키지를 import할 수 없으면 같은 모양 검사를 시험 안에 둔다.
  - `sendSoloLog`는 `${serverUrl()}/api/solo-log`로 `text/plain` POST를 보낸다.
  - `post`가 reject해도 resolve한다.
- [ ] Step 2: 실패 확인 → Step 3: 구현. `solo.ts`는 시드를 변수로 들고 `restart`에서 새로 만들고, `driver.onFinished`에서 보낸다. → Step 4: `npm test`와 `npm run typecheck` 통과 확인
- [ ] Step 5: 커밋 `Send each finished solo game to the play log`
