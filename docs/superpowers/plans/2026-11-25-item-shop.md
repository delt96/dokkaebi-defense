# 3스테이지 아이템 장터 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 3스테이지 장터에서 엽전으로 부적(사거리·힘·날쌘·약화)을 사서 들고 있다가 유닛 하나에 붙이고, 값은 봇 측정으로 정한다.

**Architecture:** 수치형 아이템(설계 A안).
- 상점 정의는 `economy.json`의 `shop`에, 상태는 `EconState.items`/`itemsBought`와 `Unit.item`에 둔다.
- 효과는 사거리(`unitRange`), 공격력(`damageBonus`), 공격 속도(`speedBonus`)를 계산하는 곳에서 더한다. 약화는 기본 공격 대상 하나에 건다.
- 새 상태 키는 처음 쓸 때만 생겨서 1·2스테이지와 아이템 없는 판의 해시가 그대로다.

**Tech Stack:** TypeScript monorepo (packages/logic · sim · client · server), vitest(`npm test`), `npm run typecheck`, tsx 스크립트.

**Spec:** `docs/superpowers/specs/2026-11-25-item-shop-design.md` (목업 `docs/design/mockups/2026-11-25-item-shop.html`)

## Global Constraints

- 3스테이지 전용이다. `data.economy`가 없는 판(1·2스테이지)에는 상점 상태·명령·화면이 없다.
- 1스테이지 골든 시험(`packages/sim/test/golden.test.ts`)이 그대로 통과해야 한다. 새 상태 키(`Unit.item`, `EconState.items`, `EconState.itemsBought`)는 쓰기 전까지 없다.
- 유닛 하나에 아이템 하나. 붙이면 옛 아이템은 사라진다.
- 조합·판매·지게로 사라지고, 이동하면 따라간다.
- `rangeCharm`은 `perGame: 1`이다.
- 서는 자리(가장자리/안쪽)는 유닛 종류의 `range`로 정한다. `units.ts` `wantEdge`, 봇 `isMelee`, 클라이언트 `fx/plan.ts` `melee`가 그 자리다.
- 약화 부적은 기본 공격의 대상 하나에만 건다. 스킬 피해·범위에는 걸지 않는다.
  - 열쇠는 `item:weakCharm:<damageType>`이다.
  - `vulnCaster`를 세우지 않는다.
  - `vulnCap`을 따른다.
- 공격력·속도 아이템은 `auraCaps` 상한 밖에서 더한다.
- 사기·붙이기는 `econ.marketOpen`이 거짓이면 `marketLocked`로 막는다. 준비 시간에도 된다.
- 조합·보관함 꺼내기·보관함 판매는 같은 유닛이 여럿이면 아이템 없는 쪽을 먼저 쓴다.
- 데이터 첫 값(가격은 측정 전 임시값):
  - `rangeCharm`: 사거리 부적, 300냥, `perGame: 1`, `{kind:'range', amount:0.5}`
  - `powerCharm`: 힘 부적, 150냥, `{kind:'attack', pct:0.2}`
  - `swiftCharm`: 날쌘 부적, 150냥, `{kind:'speed', pct:0.15}`
  - `weakCharm`: 약화 부적, 150냥, `{kind:'vuln', pct:0.1, seconds:3}`
- 사용자에게 보이는 글은 한국어다. 코드 주석은 원칙적으로 없다. 남기는 주석은 영어로, 코드만 보고 알 수 없는 것만 쓴다.
- 커밋은 `claude/firepower-check` 브랜치에 한다. main에는 올리지 않는다. 커밋 메시지 끝에 `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

## Review Focus

- **온라인 남의 판·재접속:** `UnitView.item`이 빠지면 다른 고개에 표시가 안 보이고, 재접속 뒤 내 유닛 카드에서 아이템이 사라진 것처럼 보인다. Task 5 시험이 view 왕복을 확인한다.
- **바꿔 끼우기:** 이미 붙은 유닛에 같은 아이템을 다시 붙이면 하나를 잃는 것이 맞다(규칙 그대로). 하지만 화면은 경고를 띄워야 한다. Task 6 시험이 그 문구를 고정한다.
- **아이템 붙은 유닛이 유일한 재료일 때:** 조합은 되고 아이템은 사라진다. 조합 후보에 "아이템이 사라집니다"가 떠야 한다. Task 4·6 시험이 다룬다.
- **약화 부적 + 범위 유닛:** 범위 공격으로 맞은 다른 적에는 약화가 없어야 한다. Task 3 시험이 다룬다.
- **보관함에 넣은 아이템 유닛:** 넣었다가 꺼내면 아이템이 그대로 붙어 있어야 한다. Task 4 시험이 다룬다.
